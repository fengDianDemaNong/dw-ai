# 0.1.5 功能需求清单

产品版本 0.1.5 · 文档修订 1.1 · 状态：设计中（原型可点）  
相对 0.1.4：套件组合、分产品角色、平台服务注册、租户内模块可见范围。仓建设加工定义沿用，不在此重复。

交互原型：`npm run proto -- 0.1.5` → http://127.0.0.1:4223/

**本版不交付实现。** 确认交互后再开技术清单。

| # | 需求 | 入口 | 角色 | 验收 |
|---|---|---|---|---|
| 0.0 | 每个模块支持独立 / 普通 / 多租户三种启动模式 | 启动配置 | — | 独立无用户；普通有用户无租户；多租户须组织平台且 REST 登记 |
| 0.1 | 组织平台与仓建设分两个进程、两套代码 | 4224 / 4223 | — | 4224 管租户项目；4223 只有建模；未登录从 4223 会跳回 4224 |
| 0.2 | 新建项目按同一项目 ID 同步到已启用模块 | 组织平台 · 项目 | 租户管理员 | 卡片上各模块 remoteId 等于组织 projectId |
| 1.1 | 平台只登记产品进程地址（手工或模拟心跳），不含调度/引擎 | 平台后台 · 服务注册 | 平台用户 | 仓建设在 `127.0.0.1:4223`；元数据在 `192.168.10.21:8080`；没有 DS |
| 1.1b | 租户自己登记 DolphinScheduler 与数仓引擎 | 工作台 · 计算资源 | 租户管理员 | 星河已测通 DS；启航未配则项目无「调度」分组 |
| 1.2 | 平台给租户开通的是产品上限 | 平台后台 · 租户 | 平台用户 | 星河开通仓建设+元数据+质量+服务；启航仅仓建设 |
| 1.3 | 租户内再启用模块，并设定谁能看见 | 工作台 · 模块管理 | 租户管理员 | 星河关闭「数据服务」；仓建设全员、元数据持有角色、质量仅项目管理员 |
| 1.4 | 项目侧栏 = 开通 ∩ 启用 ∩ 可见 ∩ 在线服务 | 项目壳 | 项目成员 | 张三见仓建设+元数据+质量（质量禁用：无服务）；李四见仓建设+元数据、不见质量；王五只见仓建设；启航无元数据 |
| 2.1 | 项目成员：组织角色 + 按已启用产品分栏派角 | 项目成员 | 项目管理员 | 李四：建模工程师 / 血缘分析 / 巡检员；张三各栏显示自动管理角色 |
| 2.2 | 角色管理展示组织角色 + 已启用产品的角色表 | 工作台 · 角色 | 租户管理员 | 出现「血缘分析」，不把建模工程师套到元数据 |
| 3.1 | 元数据目录 / 作业血缘 / SQL 解析 / 数据目录 / 临时表规则（embed 条） | 元数据菜单 | 见产品角色 | 有「独立产品 · 元数据」条；解析保存受血缘分析约束 |
| 3.2 | 表明细设计态血缘可跳作业血缘 | 表详情 | 读模型 | 带上 `catalog.schema.table` |

演示账号见 [03-identity-access.md](./03-identity-access.md)。

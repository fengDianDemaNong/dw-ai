# 身份与权限

产品版本 0.1.5 · 文档修订 1.2 · 状态：设计中  
相对 [0.1.4](../../0.1.4/spec/03-identity-access.md)：组织角色与产品角色拆开。三种运行模式下身份真源不同，见 [06-runtime-modes.md](./06-runtime-modes.md)。

- **独立**：无登录、无角色。不实现用户。
- **普通**：本模块本地用户 + 项目角色 + 产品角色。无租户。
- **多租户**：组织平台是人/租户/项目真源；模块只问 `authz/check`。

## 1. 两层角色（普通 / 多租户）

权限仍跟角色走，不做跨产品勾选矩阵。

**组织层（底座，尽量少）**

| 角色 | 谁任命 | 只做什么 |
|---|---|---|
| 平台用户 | 平台后台 | 开停租户、开通产品上限、登记服务、管平台账号 |
| 租户管理员 | 平台指定 / 转让 | 开项目、开账号、指定项目管理员、**裁本组织模块与可见范围** |
| 项目管理员 | 租户管理员 | 拉人、给各已启用产品派角色。各已启用产品**自动**映射为该产品的管理角色 |
| 项目成员 | 项目管理员拉入 | 只在被派了角色、且模块对其可见的产品里做事 |

**产品层（各产品 manifest，跟该产品版本走）**

| 产品 | 角色 |
|---|---|
| 仓建设 | 规范管理员、建模工程师、只读 |
| 元数据 | 目录管理员、血缘分析、只读 |
| 数据质量 | 规则管理员、巡检员、只读（本版仅派角） |
| 数据服务 | 指标管理员、服务开发、只读（本版仅派角） |
| 开发 / 沉淀 | 管理员、只读（默认可开通，演示未给星河） |

调度不是产品角色。DolphinScheduler 由租户在「计算资源」自管；能进仓建设的人，在集群已测通时能看调度任务。

底座只存 `项目 + 人 + 产品码 + 角色码`。不理解「建模工程师」的语义。

模块可见范围（租户策略）与产品角色叠加：先决定能不能看见菜单，再决定能不能点进去做事。

## 3. 与 0.1.4 的兼容观感

只开仓建设时：项目管理员仍能写规范、发布模型（自动映射规范管理员）。成员被派「建模工程师」时行为与旧版建模工程师相同。组合客户在成员页看到的是按产品分栏，而不是一个下拉三个仓建设角色。

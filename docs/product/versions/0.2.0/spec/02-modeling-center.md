# 建模中心

产品版本 0.2.0 · 文档修订 1.3 · 状态：设计中  
依据：[00-platform.md](./00-platform.md)、[01-spec-center.md](./01-spec-center.md)、[05-products.md](./05-products.md)

相对 [0.1.4](../../0.1.4/spec/02-modeling-center.md)：字段加工、多源 DWS、设计态影响面沿用。表明细「血缘」为设计态；可跳到已接入的元数据产品看作业血缘。两张图不互相覆盖。建模写仍须项目管理员或仓建设建模工程师 / 规范管理员。

建模中心管理**逻辑表**，并按规范生成、审核从源层到明细、从明细到汇总的草案。  
不管理指标定义，不指定物理存储格式。

## 1. 导航与页面

| 入口 | 职责 |

| 各分层（动态） | 按主题域看总览、表列表、表明细 |
| **AI 设计（每层）** | 用对话设计新表或改已有表，确认后写入草稿 |

当前产品仍保留两条规则生成路径：ODS → DWD、DWD → DWS。其它层用手建或该层 AI 设计。

未归属主题域的表归在「未归属」。

无 `model_design` 时，各层「AI 设计」入口可见但禁用，文案「本组织未开通此项」。

开发中心若仍出现「血缘追踪」，只作跳转到本中心「影响与血缘」，不维护第二套图。

## 2. 逻辑表

表描述业务结构，不描述落在哪种文件格式或哪套引擎上。

**表：** 表名、中文说明、分层、主题域、粒度、周期、分区、状态（草稿 / 已发布 / 已下线）、数据等级、**来源表列表**、**关联**、表级过滤（可选）、**当前版本号**。

兼容：仅一张来源时，仍可用「来源表」一栏展示；内部等于来源列表第一项。不再把「只能一张来源」当作模型限制。

**字段：** 字段名、逻辑类型、注释、是否不为空、默认值、是否敏感、字段等级、枚举值（可选）、**加工定义**（见第 2.3 节）。

逻辑类型为跨引擎名称，例如字符串、整数、高精度小数、布尔、日期时间。  
**不为空**勾选后才能设默认值；默认值随建表语句写出。

建表界面不出现「存储 / ORC」一类引擎细节。

状态：草稿可改；**保存编辑后回到草稿**，不记版本。点**发布**才生成新版本（可填备注）。已下线不可再作为生成目标的首选（列表仍可见）。

### 2.0 来源与关联

一张表可以声明 0 条、1 条或多条来源（本项目内其它逻辑表）。每条来源有**别名**（如 `o`、`r`）。

多来源时必须写清**关联**：

- 左别名、右别名
- 等值键（可多对，如 `o.shop_id = r.shop_id` 且按分区对齐）
- 关联类型（内连接 / 左连接）

表级过滤为人读条件（如「只要已支付」），可选。分区字段默认按同一业务日对齐，不必再画一条边。

没有来源的表（如手工录入的 ODS）允许。有来源但未写字段加工时，结构仍可保存，字段标「尚未定义逻辑」。

## 2.1 AI 设计表（每层）

需要能力 `model_design`。每一层总览提供 **AI 设计**；表明细可 **AI 改这张表**。对话只针对**当前层**。

流程：

1. 用户用自然语言说明要建的表、要改的字段、粒度或来源。
2. 助手给出本层草案（可含多张表）：新建或修改已有表，含表名、说明、主题域、粒度、字段，**尽量带加工定义**。
3. 用户可继续对话调整草案，勾选要采纳的表。
4. **确认写入系统**：新建表以**草稿**落入本层；修改已有表立即更新结构并生成新版本。无「写模型」权限的人只能看草案，不能写入。写入前若改的是已有表且存在下游，须展示影响清单（见第 6.1 节）。

本版加深（相对 0.1.3）：

- 代发必须带：**本层规则**（命名 / 脱敏 / 空值等）、**已有表名**、**主题域编码**。改表时带当前字段**及已有加工定义**。
- 系统提示来自租户槽位 `model.system`，占位符含 `{{layer}}` `{{focus_table}}` `{{domains}}` 等，见 [01-spec-center.md](./01-spec-center.md) 第 6.1 节。本版不新增槽位。
- 页上标明「已带本项目规范」，避免用户以为模型不看本项目约定。
- 采纳前与当前表可对比（沿用表版本，含口径）。`model:write` 才能写入。
- 已开启大模型才读提示词并代发；未开启或代发失败：提示后回退内置草案。
- AI 给出的 SQL 只当草案，**写入前须落成第 2.3 节结构**；模型乱写的语句不能当真源。
- AI 设计不替代规范中心；命名、分层策略仍以本项目规范为准。存在明显规范问题时，草案上给出说明，但不阻塞对话。

## 2.2 模型版本

**只有发布才形成一版。** 手工新建 / 编辑、AI 采纳、从历史版本写回，都先落到**草稿**，不记版本。点「发布」时生成新版本，并可填写备注。无结构变化时发布不记新版本。

| 能力 | 说明 |
|---|---|
| 查看历史 | 表明细进入版本页，按时间列出版本号、操作人、**发布备注** |
| 对比 | 任选两版，对比表属性、字段（新增 / 删除 / 类型或注释）、来源与关联、字段口径与加工。**下方直接列出从 A 版 → B 版的结构变化语句**（`ADD COLUMNS` / `CHANGE COLUMN` / `DROP COLUMN` 等逻辑 DDL，不按方言拆、不执行） |
| 查看某版 | 只读展示该版快照，不改当前表 |
| 切换为当前 | 把某历史版写回当前表，变为**草稿**。写回前展示影响清单。再发布才记新版本。历史记录不删除、不改写 |

当前已发布内容等于最新一版快照。草稿可以和上一发布版不同。快照须包含来源、关联与字段加工。

## 2.3 字段加工定义

每个字段一条加工定义。人读口径与机器可读结构并存。**加工 DML 由本定义 + 表级来源/关联生成**，与建表 DDL 同属逻辑 SQL 视图，不是第二种真源。本版只出一份 DML，不按方言拆三套。五种类型的说明见 [01 §5.1](./01-spec-center.md)。

**人读：** `desc`（业务口径）。空 = 尚未定义逻辑，不影响保存结构。有结构化来源或运算时，产品上应提示补一句口径。

**机器可读：**

| 项 | 说明 |
|---|---|
| `kind` | `passthrough` 透传 · `transform` 转换 · `aggregate` 聚合 · `derive` 派生 · `constant` 常量 |
| `sources` | 来源列，`{ alias, column }`，可多条 |
| `op` | 如 `SUM`、`COUNT_DISTINCT`、`HASH`、`MASK`，可空 |
| `expr` | 派生或转换的短表达式，可引用别名列或**本表其它字段名** |
| `filter` | 该字段额外条件，可空 |

典型：

| 类型 | 何时 | 例子 |
|---|---|---|
| 透传 | 维度原样带下 | `o.shop_id` |
| 转换 | ODS→DWD 脱敏 / 时间 / 空值 | `hash(u.mobile)` |
| 聚合 | DWS 度量 | `COUNT(DISTINCT o.order_id)`，可带 `o.status='paid'` |
| 派生 | 多源或本表计算 | `gmv - refund_amt` |
| 常量 | 分区、标记 | 分区 `dt`、字面量 |

建模中心**不注册指标**。指标以后可绑到「某表某字段」，复用同一条口径。一张 DWS 服务多组查询，不是一张表一个指标。

## 3. 逻辑 SQL（DDL 与 DML）

逻辑 SQL 是逻辑表的**视图**，不是第二种真源。真源仍是表结构 + 来源/关联 + 字段加工。表明细同一块里可切换：

- **建表 DDL**：按目标引擎查看 Hive / Doris / MySQL。
- **加工 DML**：由第 2.0 + 2.3 节生成一份 `INSERT … SELECT`（逻辑 SQL，可含 `${bizdate}`），不按方言拆三套。

产品要求：

- 不在语句中指定用户可选的存储格式。
- 用户填写的安全信息写入注释：表级含等级及查询/导出策略、主题域、粒度（仅已填项）；字段级含等级、敏感标记。字段未单独设等级则继承表等级。
- 不为空且已填默认值时，DDL 中带默认值。
- 建表过程中即可预览；DDL 方言可切换，DML 本版只有一份。
- 未写加工的字段在 DML 里用注释占位，不编造运算。无来源时 DML 只给说明注释。

点字段打开的抽屉另给**该列查询 SQL**（`SELECT … FROM …`，与整表 DML 同一套生成器），可复制。未定义加工时提示无法生成，并引导去编辑。

## 4. ODS → DWD

1. 选择一张 ODS 表。
2. 按词根识别字段，建议主题域、粒度、主键。
3. 套用 DWD 层脱敏、时间格式、空值策略：禁止下沉则去掉敏感字段；掩码/哈希/加密则转换；空值打回则约束主键与分区。
4. 展示规范问题（错误 / 警告 / 说明）。**失败信息须可读**（指出哪条规则、哪个字段）。
5. 人工确认：主题域正确、粒度合适、敏感已处理。主题域把握不足时必须确认后才能过。
6. 存在规范**错误**时不能发布。
7. 具备「发布模型」权限的人审核通过后，生成已发布的 DWD 表。

发布时必须把草案上的字段处理写入 DWD **加工定义**（透传或转换），来源指向该 ODS，别名默认 `s`。不再只留一段 `etlSql` 而不落字段。

本版不强制这条生成路径也走 LLM（避免范围膨胀）。若实现窗口有余力，再把生成说明接同一套校验文案。

## 5. DWD → DWS

1. 选择**一张或多张** DWD，为每张指定别名。
2. 多表时指定关联键（至少含业务主键或店铺/用户等维度键；分区默认对齐）。
3. 选择维度（须来自已选 DWD 的字段）。当本层策略为「禁止下沉」时，不得把可识别个人身份的维度带入汇总表；违规则为错误，不能发布。
4. 添加度量：来源列 + 聚合（`SUM` / `COUNT` / `COUNT_DISTINCT` / `AVG` 等）+ 可选过滤；可再添加派生字段（引用本草案其它度量）。
5. 产出字段加工定义、预聚合逻辑 SQL、建议的质量规则。DML 由定义拼出，不写死单表 `order_cnt` / `gmv`。
6. 人工确认：汇总粒度合适、维度不含禁止下沉的信息、命名符合本层、口径读得懂。
7. 具备「发布模型」权限的人审核通过后，生成已发布的 DWS 表，**写入来源、关联与字段加工**。

汇总表服务多组查询，**不是**一张表对应一个指标。指标落地在数据服务定义；物理可以是明细计算、汇总预聚合、应用表或查询时计算。

## 6. 表明细

展示：主题域、粒度、周期/分区、等级、状态、**来源表（可多张，可点进）**、字段（含**口径 / 加工类型**）。页底一块用类型切换：**逻辑 SQL**（建表 DDL | 加工 DML）、**血缘**（上游表 → 本表 → 下游表，以及字段级上游列 / 下游表.字段）、**下游影响**（草稿相对上一发布版）。

点字段打开抽屉：完整加工定义、上游列、下游谁引用了本字段、**该列查询 SQL**（可复制）。类型名称可链到规范中心「加工类型」。

草稿表可**发布**：弹窗填写备注，并再次列出影响的下游表字段。发布后生成新版本。无「发布模型」权限的人不能发布。

可编辑、可删除。编辑保存为草稿，并列出影响的下游表字段。删除有下游时必须列出下游。产品**不自动改下游**。

### 6.1 影响面

影响图只从本项目逻辑表计算：

- **表边**：B 的来源列表含 A → 改 A 可能影响 B
- **字段边**：B 某字段的 `sources` 或派生 `expr` 引用了 A 的列（或本表另一字段）
- **边类型**：维度、度量、关联键、过滤、派生

保存 / 删除 / 从历史恢复 / AI 采纳改已有表时，对比「当前已发布（或当前）结构」与「即将写入」的差，列出下游：

| 变更 | 处理 |
|---|---|
| 只改注释、等级、敏感标记 | 不拦，清单可空或标「无结构影响」 |
| 改名、改类型、删除字段，且被引用 | 必须确认；列出下游表与字段 |
| 改口径、`op`、来源列、过滤 | 列出下游字段，标「待复核」；须确认后才能写入 |
| 改粒度或关联键 | 整张下游表警告，须确认 |
| 新增字段、新增来源但无下游引用 | 不拦 |

产品**不自动改下游**。确认后只写本表；下游保持原定义，由人去改或重新生成。

「待复核」在本版是提示态，不另建工单模块。

## 7. 规范校验页

对项目内表跑命名与词根检查，只读。发布草案时已内嵌同一套检查。本页不检查加工是否写全。

## 8. 质量规则

生成草案时可附带建议规则（主键唯一、空值率、枚举等）。  
建模中心只保存建议，不在本中心执行巡检。执行在质量或开发能力中。

## 9. 与数据服务的边界

- 指标工厂、数据市场、查询网关不放在建模侧栏。
- 建模不把「注册指标」做成建表的必经步骤。
- 旧版数据服务入口若仍保留，与新数据服务并行，不在建模中心双开。
- 字段加工不是指标定义。

## 10. 权限（产品语义）

- 看表、草案、逻辑 SQL（DDL / DML）、版本历史与对比、**影响与血缘**：需要「读模型」
- 建改删表、维护来源与加工、发起生成、**AI 草案写入系统**、**把历史版本写回为草稿**：需要「写模型」
- 打开建模 AI 入口：需要能力 `model_design`；写入另须「写模型」
- **发布表（生成新版本）**、审核通过并发布生成草案：需要「发布模型」
- 规范错误未消除时，即使有发布权限也不可通过
- 无写权限的人可以看影响清单，不能确认写入

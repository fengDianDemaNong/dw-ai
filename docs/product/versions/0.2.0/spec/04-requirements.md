# 0.2.0 功能需求清单

产品版本 0.2.0 · 文档修订 1.3 · 状态：设计中（原型可点）  
相对 0.1.4：套件组合、分产品角色、平台服务注册、租户内模块可见范围。仓建设加工定义沿用，不在此重复。

交互原型：`npm run proto -- 0.2.0` → http://127.0.0.1:4233/

交互已确认。实现按 [PRD.md](../PRD.md) 与 [docs/tech/07-0.2.0.md](../../../../tech/07-0.2.0.md)。

| # | 需求 | 入口 | 角色 | 验收 |
|---|---|---|---|---|
| 0.0 | 每个模块支持独立 / 普通 / 多租户三种启动模式 | 启动配置 | — | 独立无用户；普通有用户无租户；多租户须组织平台且 REST 登记 |
| 0.1 | 组织平台与仓建设分两个进程、两套代码 | 4234 / 4233 | — | 4234 管租户项目；4233 只有建模；未登录从 4233 会跳回 4234 |
| 0.2 | 新建项目按同一项目 ID 同步到已启用模块 | 组织平台 · 项目 | 租户管理员 | 卡片上各模块 remoteId 等于组织 projectId |
| 1.1 | 平台只登记产品进程地址（手工或模拟心跳），不含调度/引擎 | 平台后台 · 服务注册 | 平台用户 | 仓建设在 `127.0.0.1:4233`；数据地图在 `127.0.0.1:5175`；没有 DS |
| 1.1b | 租户自己登记 DolphinScheduler 与数仓引擎 | 工作台 · 计算资源 | 租户管理员 | 星河已测通 DS；启航未配则项目无「调度」分组 |
| 1.2 | 平台给租户开通的是产品上限 | 平台后台 · 租户 | 平台用户 | 星河开通仓建设+数据地图+质量+服务；启航开通仓建设+数据地图 |
| 1.3 | 租户内再启用模块，并设定谁能看见 | 工作台 · 模块管理 | 租户管理员 | 星河关闭「数据服务」；仓建设全员、元数据持有角色、质量仅项目管理员 |
| 1.4 | 项目侧栏 = 开通 ∩ 启用 ∩ 可见 ∩ 在线服务 | 项目壳 | 项目成员 | 张三见仓建设+数据地图+质量（质量禁用：无服务）；李四见仓建设+数据地图、不见质量；王五见数据地图但禁用；启航也能进数据地图 |
| 2.1 | 项目成员：组织角色 + 按已启用产品分栏派角 | 项目成员 | 项目管理员 | 李四：建模工程师 / 血缘分析 / 巡检员；张三各栏显示自动管理角色 |
| 2.2 | 角色管理展示组织角色 + 已启用产品的角色表 | 工作台 · 角色 | 租户管理员 | 出现「血缘分析」，不把建模工程师套到元数据 |
| 0.3 | 跨服务只传 `tenant_code` / `project_code` / `user_id`，不用各库数字 id | 头 / `#boot=` / `/internal/v1/projects` | — | 见 [07-context.md](./07-context.md)；数据地图 iframe 的 boot 是 code 不是 `t-*` |
| 3.1 | 数据地图：全文检索 / 血缘 / 数据目录 / 临时表规则 / SQL 解析 / 元数据（iframe 嵌入 sql-lineage） | 数据地图菜单 | 见产品角色 | 分组标题为「数据地图」；iframe 去对方壳；`#boot=` 带 tenantCode/projectCode |
| 3.3 | 设置：元数据服务 + 数据地图设置（水印 / 缩略图） | 设置菜单 | 见产品角色；改服务须目录管理员或项目管理员 | 分组标题为「设置」；嵌入对方页，不出现对方的租户/项目/主题 |
| 3.2 | 表明细设计态血缘可跳作业血缘 | 表详情 | 读模型 | 带上 `catalog.schema.table` |
| 4.1 | 分层规范按项目隔离；空项目可导入模板 | 规范中心 · 分层规范 | 写规范 | 默认项目 / 不勾模板的新项目列表为空；导入四层后仅本项目可见；交易数仓仍有 ODS–ADS |

# 规范中心

产品版本 0.2.0 · 文档修订 1.4 · 状态：设计中  
依据：[00-platform.md](./00-platform.md)

相对 [0.1.4](../../0.1.4/spec/01-spec-center.md)：规范对象不变。写规范仍须组织「项目管理员」或仓建设「规范管理员」。主题域 / 分层 / 等级 / 词根 / 导入导出、规范设计与问答沿用。**规范中心说明五种加工类型，不维护某张表某列怎么算**（字段实例在建模中心）。

规范中心维护**当前项目**的约定：主题域、分层、词根、数据等级、**加工类型说明**，以及导入导出。  
约定被建模、生成草案、对外访问共同遵守。规范中心不建仓表。

## 1. 页面职责

| 入口 | 职责 |
|---|---|
| AI 设计规范 | 按能力走设计或问答。设计：生成提案（主题域、分层、词根、等级），必须人工采纳后才写入。问答：只解释已有约定，不写库 |
| 主题域 | 增删改主题域 |
| 分层规范 | 增删改分层及本层策略；允许自定义分层（如 DIM、STG） |
| 数据等级 | 增删改等级；可套模板 |
| 词根库 | 增删改词根，供命名识别与校验 |
| **加工类型** | 只读说明：透传 / 转换 / 聚合 / 派生 / 常量。不可增删改类型 |
| 导入导出 | 导出/导入整包规范，不含表数据 |

新建项目时可选择「导入通用规范模板」。空项目不预置演示业务表。

无 `spec_design` 且无 `spec_ask` 时，侧栏「AI 设计规范」可见但禁用，文案「本组织未开通此项」。

## 2. 主题域

每个项目内编码唯一。字段包括：编码、名称、业务定义、业务/技术/数据负责人、关联域、核心实体。

表归属主题域；命名中的主题域段引用编码。删除前须无表引用，或先迁移归属。

## 3. 分层规范

分层编码为开放字符串，不限于 ODS / DWD / DWS / ADS。

每层可配置：

| 项 | 含义 |
|---|---|
| 命名说明 | 本层表名如何写 |
| 保留策略 | 生命周期说明 |
| 对外服务 | 禁止 / 需审批 / 允许。参与访问裁决，不阻止建表 |
| 字段格式 | 字段命名与格式约定 |
| 时间格式 | 日期、时间戳格式 |
| 脱敏 | 保持原文 / 掩码 / 哈希 / 加密 / 禁止下沉 |
| 空值 | 保留 / 默认填充 / 空值打回，及填充说明 |

分层按项目隔离：只认本项目的分层行，不共享、不回退到全局。空项目列表为空；可在本页导入模板，或创建项目时勾选「导入通用规范模板」。

产品内置层默认只在「新增某一层」时填表单，不自动出现在列表里：

- ODS：可明文，空值保留
- DWD：敏感须脱敏后入明细
- DWS：不得保留可识别个人身份的字段（禁止下沉）
- ADS：对外前按应用再处理

侧栏建模分组的分层顺序与本项目分层配置一致。空项目建模分组没有 ODS–ADS。  
删除分层前：该层不能再有表。

## 4. 数据等级

等级是项目内编码（模板可用 L1–L4，但产品不把四级写死为唯一体系）。

每级包括：编码、名称、排序、颜色、查询策略、导出策略、要求说明、适用示例。

查询：可直接查 / 登录后可查 / 审批后可查 / 禁止查询。  
导出：可导出 / 审批后导出 / 禁止导出。

表可设等级；字段可设等级，空则继承表。  
有效等级用于：访问裁决、建表与 DDL 注释中的安全信息。

内置模板：通用四级、通用三级、广告四级。套用时可覆盖或合并；编码冲突须明确提示。

被表或字段引用的等级编码不可删，只可改策略与说明。

## 5. 词根

词根分业务、技术、时间三类。用于字段识别、建议名、命名校验。  
无法匹配词根时默认告警，不阻断发布（除非项目日后将命名设为强制——首期非强制）。

## 5.1 加工类型

本页解释项目里字段加工**怎么分类**，与建模中心 [02 §2.3](./02-modeling-center.md) 用同一套五种类型。产品写死，管理员不能增删改类型（不是第二套词根）。

| 类型 | 何时用 | 和相邻类型的差别 | 例子 |
|---|---|---|---|
| 透传 | 上游一列原样落到本列 | 不改值、不压行 | `o.user_type` → `user_type` |
| 转换 | 仍是一行对一行，但值被处理 | 不是汇总；不是用本表其它字段再算 | `hash(u.mobile)`、状态码映射 |
| 聚合 | 多行收成一行 | 必须有 SUM / COUNT 等；粒度由维度决定 | `SUM(o.order_pay_amt)` → `gmv` |
| 派生 | 用本表已算出的字段再算 | 不再直接扫源表聚合 | `gmv - refund_amt` → `net_gmv` |
| 常量 | 与源数据无关 | 固定值或分区键 | 分区 `dt`、字面量 |

适用分层（说明用，不强制拦截）：透传/转换常见于 ODS→DWD；聚合/派生常见于 DWD→DWS；常量各层都可用。

**某列的口径、来源、运算只在建模中心写。** 本页不出现表名、不生成 SQL。导入导出不含加工类型（类型是产品内置）。

## 6. AI 提案（设计）

需要能力 `spec_design`，同步需要「写规范」。

输出可含：主题域、分层、词根、等级、命名说明。  
采纳前必须人工确认。采纳只写规范，不自动建表。

本版加深：

- 代发时附带**当前项目**已有主题域 / 分层 / 等级 / 词根摘要（编码 + 名称即可）。
- **默认增量补全**：在已有约定上补充，禁止无声明覆盖整包分层。覆盖须勾选现有「覆盖已有编码」。
- 草案每条尽量带一句理由（引擎 rationale + 模型说明）。
- 已开启大模型：组 **本项目上下文 + 租户 `spec.system` 槽位** 后代发；失败则提示并回退内置草案。
- 未开启大模型：走内置草案，**不读**租户提示词槽位。

## 6.1 工作台提示词

工作台「设置」在大模型下方增加 **AI 提示词**。按槽位存，不让用户从零写整套产品逻辑。

本版槽位（设置页同时标明对话接口、确认接口与会改的数据）：

| 槽位 | 用途 | 对话 | 确认后写库 |
|---|---|---|---|
| `spec.system` | 规范设计系统提示 | `POST /api/ai/chat` | `PUT /api/projects/{id}/spec`（主题域 / 分层 / 等级 / 词根） |
| `spec.ask.system` | 规范问答系统提示 | `POST /api/ai/chat` | 不写库 |
| `model.system` | 建模系统提示（见 [02-modeling-center.md](./02-modeling-center.md)） | `POST /api/projects/{id}/layers/{layer}/ai/chat` | `POST .../ai/apply`（本层表 / 草稿，记版本） |

从 ODS/DWD 生成没有提示词槽，确认后走普通 `tables` / `drafts`。

规则：

- 产品内置一套默认（中文、数仓语境），租户打开即用。
- 管理员可改；每槽提供「恢复默认」。
- 只存相对默认的覆盖。GET 带回 `defaults` + `overrides` + 解析后的 `effective`。
- 正文支持占位符，代发前由**服务端**替换。改槽位时页面展示可用变量：
  - `{{project}}` 项目名称
  - `{{domains}}` 主题域摘要
  - `{{layers}}` 分层摘要
  - `{{roots}}` 词根摘要
  - `{{grades}}` 等级摘要
  - `{{layer}}` 当前建模层（规范槽可忽略）
  - `{{focus_table}}` 当前关注表（规范槽可忽略）
- 密钥仍加密不回传；提示词明文回给租户管理员（不是秘密）。
- 未开大模型：对话仍走内置草案，**不读租户槽位**（避免「以为改了提示词却没调模型」）。页面提示「先启用大模型，提示词才会用于代发」。
- 本版提示词只按**租户**，不按项目分叉。

## 6.2 规范问答

需要能力 `spec_ask`，权限只需「读规范」。

- 无 `spec:write`，或租户 / 授权码仅开通 `spec_ask`（没有 `spec_design`）时，本页走问答槽。
- 只出文字，解释当前项目已有约定；右侧不出现可同步草案（或草案区只读、无「确认同步」）。
- 代发使用 `spec.ask.system`，同样注入项目规范摘要。
- 不能靠问答路径把草案写入规范库。

同时开通设计与问答、且当前用户有 `spec:write`：默认走设计；页上可切到问答（切走后不出现同步按钮）。

## 7. 导入导出

导出包标识为产品格式版本（实现层规定文件头）。内容仅四类规范及来源租户/项目名称，**不含表、草案、作业、加工类型**（五种类型为产品内置，见第 5.1 节）。

导入在当前项目内按编码合并。正在被表引用的分层编码、等级编码不可从导入中删除。

## 8. 规范如何约束下游（产品语义）

| 规范 | 约束 |
|---|---|
| 主题域 | 表归属、命名中的域、生成时的归域 |
| 分层列表 | 合法分层、侧栏、缺省脱敏/空值 |
| 脱敏 / 空值 | 生成明细或汇总草案时的转换与拦截 |
| 对外服务 | 查询与服务是否允许或要审批 |
| 数据等级 | 表/字段可选值、注释、访问严度 |
| 词根与命名 | 校验与建议名 |
| 加工类型 | 只约束分类语义；不替代字段加工实例 |

访问裁决取「分层对外服务」与「表/字段有效等级」中更严的一方。禁止严于审批，审批严于登录，登录严于允许。

## 9. 权限（产品语义）

- 看规范、导出：需要「读规范」（项目管理员、建模工程师、只读访客）
- 改规范、导入、套模板、采纳提案：需要「写规范」，**仅项目管理员**。建模人员不能改规范。
- 规范问答：需要「读规范」+ 能力 `spec_ask`
- 规范设计并同步：需要「写规范」+ 能力 `spec_design`

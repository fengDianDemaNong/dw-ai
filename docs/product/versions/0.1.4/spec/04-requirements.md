# 0.1.4 功能需求清单

产品版本 0.1.4 · 文档修订 1.2 · 状态：设计中（原型可点）  
依据：[00-platform.md](./00-platform.md)、[01-spec-center.md](./01-spec-center.md)、[02-modeling-center.md](./02-modeling-center.md)、[03-identity-access.md](./03-identity-access.md)

本篇把已确认的产品能力拆成**可验收条目**。模式列：`multi` 仅多租户；`standard` 仅普通模式；`both` 两种都要。角色列为空表示所有已登录且有入口权限的人。

交互原型：`npm run proto -- 0.1.4` → http://127.0.0.1:4213/  
Release 摘要：[../RELEASE.md](../RELEASE.md)

## 0. 交付边界

**本版交付：** 0.1.3 已确认能力 + **字段加工定义** + **多源 DWS 生成** + **影响清单与血缘** + **规范中心加工类型说明** + **逻辑 SQL（建表 DDL | 加工 DML）** + **表草稿/发布记版本** + **版本对比结构变化语句**。

**本版不交付：** 指标工厂；调度 / 质量巡检执行；跨项目血缘；SQL 反解析；自动改下游；按方言三套 INSERT；新 AI 槽位或新权限码；规范中心增删改加工类型。开发中心 / 沉淀优化 / 数据服务在原型侧栏可点，除血缘跳转外仍为占位。

**相对 0.1.3：** 身份、SKU、提示词、知识库沿用。增量在规范中心（加工类型只读说明）与建模中心。

1.x–6.x 沿用 0.1.1 验收；第 7–11 节沿用 0.1.3。完整 0.1.3 条目见 [0.1.3 spec/04](../../0.1.3/spec/04-requirements.md)。第 12 节为本版新增。

## 8. AI 能力开通

| # | 需求 | 模式 | 角色 | 验收要点 |
|---|---|---|---|---|
| 8.1 | 平台不管理 AI 能力勾选；开通仓建设则 `spec_design` / `spec_ask` / `model_design` 三项全开 | multi | 平台用户 | 租户新建 / 编辑页无 AI 能力区；关仓建设则三项无效 |
| 8.2 | 授权码生成 / 编辑可勾选同样三项；空 = 不限制 | multi | 租户管理员 | 持码进入后有效能力 = 租户仓建设许可 ∩ 授权码 |
| 8.3 | 无 `spec_design` 且无 `spec_ask`：「AI 设计规范」可见但禁用 | both | 项目成员 | 文案「本组织未开通此项」；普通模式三项默认开，不出现未开通 |
| 8.4 | 无 `model_design`：各层「AI 设计」可见但禁用 | both | 项目成员 | 同上文案 |
| 8.5 | `spec_design` 同步仍须 `spec:write`；`spec_ask` 有 `spec:read` 即可；`model_design` 写入仍须 `model:write` | both | — | 不能靠拼 URL 绕过；无写权限不能提交 |
| 8.6 | Session / 前端 `hasAiCap(cap)` 与 `hasModule` 并列 | both | — | 平台访客按交集计算 |

## 10. 规范 / 建模 AI 加深

| # | 需求 | 角色 | 验收要点 |
|---|---|---|---|
| 10.1 | 规范设计代发附带当前项目主题域 / 分层 / 等级 / 词根摘要 | 写规范 + `spec_design` | 默认增量补全；无声明不覆盖整包分层 |
| 10.2 | 覆盖已有编码必须勾选「覆盖已有编码」 | 同上 | 未勾选则跳过已存在编码 |
| 10.3 | 草案每条尽量带一句理由 | 同上 | 引擎 rationale 或模型说明可见 |
| 10.4 | 无 `spec:write` 或仅开通 `spec_ask`：走问答槽，只出文字，右侧无同步按钮（草案只读或不出现） | 读规范 + `spec_ask` | 不能从问答写入规范 |
| 10.5 | 同时有设计能力与写权限：默认设计，可切问答 | 项目管理员 | 切到问答后同步按钮消失 |
| 10.6 | 建模 AI 代发带本层规则、已有表名、主题域编码；改表带当前字段 | 读模型 + `model_design` | 页上标明「已带本项目规范」 |
| 10.7 | 采纳前可与当前表对比（沿用表版本）；写入须 `model:write` | 写模型 | 新建草稿；改已有表记版本 |
| 10.8 | 已开大模型：system = 有效提示词 + 注入的项目摘要，不再使用写死的一句人设 | — | body 带 `slot`、`projectId`（规范页必带） |
| 10.9 | 代发失败：提示后回退内置草案 | — | 与现建模页一致 |
| 10.10 | ODS→DWD / DWD→DWS 发布前规范校验失败信息可读 | 写模型 / 发布 | 指出规则与字段；本版不强制生成走 LLM |

## 12. 字段加工与影响面（相对 0.1.3）

| # | 需求 | 模式 | 角色 | 验收要点 |
|---|---|---|---|---|
| 12.1 | 表可维护多来源（别名）与关联（等值键、内/左连接） | both | 写模型 | 单来源仍展示「来源表」；多来源须能保存并在表明细列出 |
| 12.2 | 字段可写口径 + 加工类型（透传/转换/聚合/派生/常量）及来源列 / 运算 / 过滤 | both | 写模型 | 未写逻辑可保存结构，列表标「尚未定义」；点字段见完整定义 |
| 12.3 | 表明细「逻辑 SQL」可切建表 DDL 与加工 DML；DML 由定义生成，不当第二真源 | both | 读模型 | 改加工后 DML 跟着变；未定义字段用注释占位；DDL 仍可切 Hive/Doris/MySQL，DML 一份 |
| 12.4 | DWD→DWS 可选多张 DWD，选维度并添加度量（列+聚合+过滤），可加派生 | both | 写模型 / 发布 | 发布后 DWS 带 sources/joins/logic；禁止下沉的 PII 维度仍为错误 |
| 12.5 | ODS→DWD 发布把字段处理写入 DWD 加工（来源=该 ODS） | both | 发布模型 | 不再只有一段 ETL 文本 |
| 12.6 | 保存已有表：只改注释/等级不拦；改名/类型/删除且被引用须确认；改口径标待复核；改粒度或关联键整表警告。保存后为草稿 | both | 写模型 | 清单含下游表与字段；确认后只写本表为草稿，不改下游、不记版本 |
| 12.7 | 删除有下游时列出引用，不能只问「确定」 | both | 写模型 | 确认后删除本表，下游仍在 |
| 12.8 | 表明细展示上游/下游；字段抽屉看出处与被引用 | both | 读模型 | 可点进相关表 |
| 12.9 | 建模侧栏「影响与血缘」为项目表级图，可下钻字段 | both | 读模型 | 边来自 sources 与 logic，不是手动画的 |
| 12.10 | 版本对比含来源、关联、口径变化；对比下方列出 A→B 结构变化语句（ADD/CHANGE/DROP） | both | 读模型 | 语句由快照生成，不执行 |
| 12.11 | AI 改已有表写入前展示影响清单；代发可带当前加工，不新增提示词槽。写入为草稿 | both | 写模型 + `model_design` | 无写权限不能确认 |
| 12.12 | 规范中心「加工类型」只读说明五种分类，不能增删改类型 | both | 读规范 | 与建模下拉同一套文案；不出现某表某列实例 |
| 12.13 | 字段抽屉在下游引用下方展示该列可复制的查询 SQL（SELECT … FROM …）；未定义时说明无法生成并引导编辑 | both | 读模型 | 与整表 DML 同一生成器 |
| 12.14 | 表明细「发布」把草稿变为已发布并生成新版本，可填备注；发布时列出影响的下游表字段 | both | 发布模型 | 无结构变化不记新版本；不自动改下游 |
| 12.15 | 表明细展示本表血缘（上游→本表→下游，及字段级上游列/下游表.字段） | both | 读模型 | 可点进相关表 |
| 12.16 | 草稿表明细「下游影响」列出相对上一发布版受影响的下游表与字段 | both | 读模型 | 与保存/发布弹窗同一套评估 |

## 13. 非目标

与 [00-platform.md](./00-platform.md) 第 5 节及本版边界一致，本版不做：

- 平台模型目录 / 默认通道
- 租户自定义任意路由、通用后台 Chat
- 开发中心 / 质量 / 指标 AI（血缘以建模页为准）
- 提示词按项目分叉
- 登录页自助新建租户，或把项目提升成租户
- 任意勾选的权限矩阵
- 以 Casdoor 等外部 IdP 作为本版登录主路径
- 指标注册、自动改下游、跨项目血缘、SQL 反解析

# 平台原则

产品版本 0.1.0 · 文档修订 1.0 · 状态：已冻结

智仓 DW-AI 按 **租户 → 项目 → 业务对象** 组织。规范中心与建模中心属于「仓建设」能力，挂在项目下。

## 1. 身份与组织

- **用户、登录、组织**由独立身份平台提供，产品不自建账号库、不存密码。
- 身份平台中的**组织 = 租户**（如星河电商、启航科技）。
- **项目**是产品对象：一个租户下多个项目，规范与表属于项目，不属于租户全局一份。
- **项目成员与角色**在产品内维护：谁能进哪个项目、担任建模还是只读。身份平台只保证「这人是谁、属哪个组织」。

租户管理员在产品里邀请、禁用、分配项目角色，不必进入身份平台的完整管理台。身份平台控制台留给平台运维：登录方式、组织开通、同步源。

## 2. 模块（SKU）

能力按模块开通，不是按页面零散勾选。

| 模块 | 用户能进入的能力 |
|---|---|
| 仓建设 | 规范中心 + 建模中心；开发中心可挂在本模块或套件 |
| 数据服务 | 数据市场、指标工厂等（与仓建设并行，不在本文展开） |
| 数据质量 | 质量规则执行与报告（建模只产生「建议规则」） |
| 沉淀优化 | 查询反向建模，默认关闭的插件 |
| 完整套件 | 上述并集 + 完整成员管理 |

未开通的模块，侧栏不出现对应分组。套件不是第四套产品，是许可组合。

## 3. 菜单与功能

- 菜单是产品信息架构，跟版本走，**租户不能新增路径、不能改入口指向**。
- 侧栏 = 产品目录 ∩ 已开通模块 ∩ 当前项目角色权限。
- 建模中心的分层入口随**本项目已配置的分层**变化，不是写死的四层菜单。
- 功能用稳定的权限语义表达（如「改规范」「发布模型」），不用菜单编号当权限。
- 只藏菜单不够：无权限时入口、按钮、提交必须一致拒绝。

建议角色（项目级，同一人在不同项目角色可以不同）：

| 角色 | 规范 | 建模 |
|---|---|---|
| 项目管理员 | 读、写 | 读、写、发布，以及拉人 |
| 建模工程师 | 读、写 | 读、写；发布视项目是否授予 |
| 只读访客 | 读 | 读 |

个人空间（数据服务）按所有者可见，不做成菜单权限。

## 4. 与仓建设的关系

规范定义项目内约定；建模按约定管理逻辑表。  
指标定义、指标工厂、查询网关属于数据服务，不进建模中心。  
调度落地、质量任务执行属于开发中心或质量模块。

## 5. 非目标

- 在身份平台里为每个项目建一套隔离域。
- 让租户在后台拖菜单、配外链、自定义路由。
- 用通用后台脚手架替换本产品的工作台信息架构。

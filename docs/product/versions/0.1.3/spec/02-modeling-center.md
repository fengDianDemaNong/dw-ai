# 建模中心

产品版本 0.1.3 · 文档修订 1.0 · 状态：设计中  
依据：[00-platform.md](./00-platform.md)、[01-spec-center.md](./01-spec-center.md)

相对 [0.1.1](../../0.1.1/spec/02-modeling-center.md)：逻辑表、DDL、生成路径、表版本沿用。本版建模 AI 代发必须带本项目规范，写入仍须 `model:write` + 能力 `model_design`。

建模中心管理**逻辑表**，并按规范生成、审核从源层到明细、从明细到汇总的草案。  
不管理指标定义，不指定物理存储格式。

## 1. 导航与页面

| 入口 | 职责 |
|---|---|
| 各分层（动态） | 按主题域看总览、表列表、表明细 |
| **AI 设计（每层）** | 用对话设计新表或改已有表，确认后写入草稿 |
| 规范校验 | 对已有表做命名与字段约定检查，不改表 |
| 从 ODS 生成 | 由 ODS 生成 DWD 草案并审核 |
| 从 DWD 生成 | 由 DWD 生成 DWS 草案并审核 |

分层入口来自本项目分层规范。未配置的层不出现。  
自定义分层（如 DIM）与内置层共用同一套总览 / 列表 / 详情 / **AI 设计**，不各写一套产品。

当前产品仍保留两条规则生成路径：ODS → DWD、DWD → DWS。其它层用手建或该层 AI 设计。

未归属主题域的表归在「未归属」。

无 `model_design` 时，各层「AI 设计」入口可见但禁用，文案「本组织未开通此项」。

## 2. 逻辑表

表描述业务结构，不描述落在哪种文件格式或哪套引擎上。

**表：** 表名、中文说明、分层、主题域、粒度、周期、分区、状态（草稿 / 已发布 / 已下线）、数据等级、来源表（若由生成产生）、**当前版本号**。

**字段：** 字段名、逻辑类型、注释、是否不为空、默认值、是否敏感、字段等级、枚举值（可选）。

逻辑类型为跨引擎名称，例如字符串、整数、高精度小数、布尔、日期时间。  
**不为空**勾选后才能设默认值；默认值随建表语句写出。

建表界面不出现「存储 / ORC」一类引擎细节。

状态：草稿可改；已发布可改结构（每次保存生成新版本）；已下线不可再作为生成目标的首选（列表仍可见）。

## 2.1 AI 设计表（每层）

需要能力 `model_design`。每一层总览提供 **AI 设计**；表明细可 **AI 改这张表**。对话只针对**当前层**。

流程：

1. 用户用自然语言说明要建的表、要改的字段、粒度或来源。
2. 助手给出本层草案（可含多张表）：新建或修改已有表，含表名、说明、主题域、粒度、字段。
3. 用户可继续对话调整草案，勾选要采纳的表。
4. **确认写入系统**：新建表以**草稿**落入本层；修改已有表立即更新结构并生成新版本。无「写模型」权限的人只能看草案，不能写入。

本版加深：

- 代发必须带：**本层规则**（命名 / 脱敏 / 空值等）、**已有表名**、**主题域编码**。改表时带当前字段。
- 系统提示来自租户槽位 `model.system`，占位符含 `{{layer}}` `{{focus_table}}` `{{domains}}` 等，见 [01-spec-center.md](./01-spec-center.md) 第 6.1 节。
- 页上标明「已带本项目规范」，避免用户以为模型不看本项目约定。
- 采纳前与当前表可对比（沿用表版本）。`model:write` 才能写入。
- 已开启大模型才读提示词并代发；未开启或代发失败：提示后回退内置草案。
- AI 设计不替代规范中心；命名、分层策略仍以本项目规范为准。存在明显规范问题时，草案上给出说明，但不阻塞对话。

## 2.2 模型版本

每一次**写入系统的结构变更**形成一版，包括：手工新建 / 编辑、AI 采纳、从历史版本恢复。无变更不记新版本。

| 能力 | 说明 |
|---|---|
| 查看历史 | 表明细进入版本页，按时间列出版本号、操作人、说明 |
| 对比 | 任选两版，对比表属性与字段（新增 / 删除 / 类型或注释变化） |
| 查看某版 | 只读展示该版快照，不改当前表 |
| 切换为当前 | 把某历史版的结构写回当前表，并**再记一版**（说明为「从 vN 恢复」）。历史记录不删除、不改写 |

当前表内容始终等于最新一版快照。恢复不是删除中间版本。

## 3. 建表语句（DDL）

DDL 是逻辑表的**视图**，不是第二种真源。同一张表可按目标引擎查看：

- Hive
- Doris
- MySQL

产品要求：

- 不在语句中指定用户可选的存储格式。
- 用户填写的安全信息写入注释：表级含等级及查询/导出策略、主题域、粒度（仅已填项）；字段级含等级、敏感标记。字段未单独设等级则继承表等级。
- 不为空且已填默认值时，语句中带默认值。
- 建表过程中即可预览，方言可切换。

加工/插入用的参考 SQL 首期保持一份，不按方言拆成三套。

## 4. ODS → DWD

1. 选择一张 ODS 表。
2. 按词根识别字段，建议主题域、粒度、主键。
3. 套用 DWD 层脱敏、时间格式、空值策略：禁止下沉则去掉敏感字段；掩码/哈希/加密则转换；空值打回则约束主键与分区。
4. 展示规范问题（错误 / 警告 / 说明）。**失败信息须可读**（指出哪条规则、哪个字段）。
5. 人工确认：主题域正确、粒度合适、敏感已处理。主题域把握不足时必须确认后才能过。
6. 存在规范**错误**时不能发布。
7. 具备「发布模型」权限的人审核通过后，生成已发布的 DWD 表。

本版不强制这条生成路径也走 LLM（避免范围膨胀）。若实现窗口有余力，再把生成说明接同一套校验文案。

## 5. DWD → DWS

1. 选择 DWD 与维度组合。
2. 当本层策略为「禁止下沉」时，不得把可识别个人身份的维度带入汇总表；违规则为错误，不能发布。
3. 产出汇总逻辑、预聚合参考 SQL、建议的质量规则。
4. 人工确认：汇总粒度合适、维度不含禁止下沉的信息、命名符合本层。
5. 同样须「发布模型」权限。规范错误信息同样须可读。

汇总表服务多组查询，**不是**一张表对应一个指标。指标落地在数据服务定义；物理可以是明细计算、汇总预聚合、应用表或查询时计算。

## 6. 表明细

展示字段、有效等级、不为空与默认值。  
DDL 区切换方言，注释规则与建表预览相同。  
可编辑、可删除（删除须确认；已被下游引用时产品上应提示，首期至少确认）。

## 7. 规范校验页

对项目内表跑命名与词根检查，只读。发布草案时已内嵌同一套检查。

## 8. 质量规则

生成草案时可附带建议规则（主键唯一、空值率、枚举等）。  
建模中心只保存建议，不在本中心执行巡检。执行在质量或开发能力中。

## 9. 与数据服务的边界

- 指标工厂、数据市场、查询网关不放在建模侧栏。
- 建模不把「注册指标」做成建表的必经步骤。
- 旧版数据服务入口若仍保留，与新数据服务并行，不在建模中心双开。

## 10. 权限（产品语义）

- 看表、草案、DDL、版本历史与对比：需要「读模型」
- 建改删表、发起生成、**AI 草案写入系统**、**把历史版本切换为当前**：需要「写模型」
- 打开建模 AI 入口：需要能力 `model_design`；写入另须「写模型」
- 审核通过并发布草案：需要「发布模型」
- 规范错误未消除时，即使有发布权限也不可通过

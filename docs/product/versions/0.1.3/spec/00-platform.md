# 平台原则

产品版本 0.1.3 · 文档修订 1.1 · 状态：设计中  
相对 [0.1.1](../../0.1.1/spec/00-platform.md)：本版在仓建设下增加 **AI 能力**（随模块自动全开，平台不单独勾选），并约定工作台提示词归属。身份、三套界面、模块 SKU 沿用 0.1.1。

智仓 DW-AI 按 **项目 → 业务对象** 组织；是否再套一层租户，由**服务启动配置**决定。规范中心与建模中心属于「仓建设」能力，挂在项目下。

## 0. 部署模式（启动时确定）

服务启动时读取配置，二选一，运行中不能改。改模式必须重启。

| 模式 | 配置值 | 有什么 |
|---|---|---|
| 多租户 | `multi` | 平台后台、租户、选租户、授权码、转让租户管理员。组织 = 租户。 |
| 普通 | `standard` | **没有**平台后台，**没有**租户相关功能。登录后直接进项目工作台。用户、项目、项目角色仍在。 |

普通模式适合单家企业自用；多租户适合平台运营多家企业。

## 1. 身份与组织

- **用户与登录由产品自建**：账号、密码、停用、重置密码都在产品里，不依赖外部身份平台。
- **多租户时**：组织 = 租户。一个人可以属于多个租户；登录后若不止一个可用租户，必须先选租户。平台用户进租户必须授权码。
- **普通模式时**：没有租户概念，也不出现平台后台、选租户、授权码、转让租户管理员。
- **项目**仍是隔离单位：规范与表属于项目。角色见 [03-identity-access.md](./03-identity-access.md)。

多租户下，租户不能在登录页自助开通。开通租户、指定该租户的第一位管理员、新增平台用户，只在平台后台完成。

## 2. 模块（SKU）

能力按模块开通，不是按页面零散勾选。多租户由平台用户为每个租户勾选；普通模式在启动配置里对本环境开通。

| 模块 | 用户能进入的能力 |
|---|---|
| 仓建设 | 规范中心 + 建模中心；开发中心可挂在本模块或套件 |
| 数据服务 | 数据市场、指标工厂等（与仓建设并行，不在本文展开） |
| 数据质量 | 质量规则执行与报告（建模只产生「建议规则」） |
| 沉淀优化 | 查询反向建模，默认关闭的插件 |
| 完整套件 | 上述并集 + 完整成员管理 |

未开通的模块，侧栏不出现对应分组。套件不是第四套产品，是许可组合。

## 2.1 AI 能力（本版新增，挂在仓建设下）

AI 是**可开通的能力项**，不替代模块勾选。未开通仓建设则 AI 项无效。

本版交付三项（只读问答单独一项，避免访客误同步）：

| 能力码 | 名称 | 做什么 |
|---|---|---|
| `spec_design` | 规范设计 | 对话生成主题域 / 分层 / 等级 / 词根草案，勾选后同步 |
| `spec_ask` | 规范问答 | 只读问答，解释本项目已有约定，不写库 |
| `model_design` | 分层建模 AI | 每层对话设计或改表，勾选后写入 / 记版本 |

规则：

- **平台不单独勾选 AI 能力**。开通仓建设则三项全开；未开通仓建设则三项无效。
- **授权码**可勾选这三项。空 = 不限制。持码进入后取 **租户仓建设许可 ∩ 授权码**。见 [03-identity-access.md](./03-identity-access.md)。
- **角色**仍约束写入：`spec_design` 须 `spec:write` 才能同步；`spec_ask` 有 `spec:read` 即可；`model_design` 写入须 `model:write`。
- 无能力时入口**可见但禁用**，文案「本组织未开通此项」。不从侧栏抹掉，避免用户以为产品没有这项。
- **普通模式**：三项默认全开，不做第二套 SKU。普通模式不出现「未开通」（工作台可关的是大模型通道与提示词覆盖，不是平台 SKU）。

本版不新开平台「通用 Chat」，不交付开发中心 / 数据服务 / 质量 AI。

## 3. 菜单与功能

- 菜单是产品信息架构，跟版本走，**租户不能新增路径、不能改入口指向**。
- 进项目之前的租户工作台主菜单是 **系统管理**；子菜单为用户管理、角色管理、项目管理、知识库、设置。**只有租户管理员能进入工作台**；普通成员、项目管理员、建模工程师登录后直接进已加入的项目（概况）。
- **知识库**：按引擎（Hive / Spark / ClickHouse / Doris）提供操作手册（本版先覆盖建表、改表、分区等）。租户管理员在**项目管理编辑**或工作台「知识库」按项目勾选引擎（同一份设置）；项目内「知识库」只显示已开通引擎。内置手册不可改路径。租户管理员可按 JSON / Markdown 模版导入补充篇（同引擎同 id 覆盖展示）。
- 平台后台主菜单是 **平台管理**；子菜单为租户、平台用户、设置。
- **外观相互独立**：平台管理里改的主题、菜单位置只作用于平台后台，不带到任何租户。租户工作台「设置」里改的主题、菜单位置作用于**该租户**的工作台和项目，与平台后台互不影响；不同租户各记一份。默认菜单在左侧。
- **大模型**：只在租户工作台「设置」里配置（服务商、接口地址、密钥、模型名）。按租户隔离，平台后台没有这项；未开启时对话仍用产品内置草案。
- **AI 提示词**（本版）：工作台「设置」在大模型下方按槽位编辑，产品内置一套中文默认，管理员可改、可恢复默认。未开大模型时不读租户槽位。详见 [01-spec-center.md](./01-spec-center.md) 第 6.1 节。
- 进项目后侧栏只保留规范 / 建模等产品目录。租户管理员可点顶栏租户名或个人信息「返回工作台」；其他用户看不到工作台入口。概况页顶栏右侧可切换项目（仅当可进项目多于 1 个时显示）。
- 侧栏 = 产品目录 ∩ 已开通模块 ∩ 当前项目角色权限。AI 入口另 ∩ 已开通 AI 能力（无能力则禁用而非隐藏）。
- 建模中心的分层入口随**本项目已配置的分层**变化，不是写死的四层菜单。
- 功能用稳定的权限语义表达（如「改规范」「发布模型」），不用菜单编号当权限。
- 只藏菜单不够：无权限时入口、按钮、提交必须一致拒绝。

建议角色（项目级，同一人在不同项目角色可以不同）：

| 角色 | 规范中心 | 建模中心 |
|---|---|---|
| 项目管理员 | 查看，以及新增 / 修改 / 删除 / 导入 / 采纳提案 | 读、写、发布，以及拉人 |
| 建模工程师 | **只能查看**（含导出）；可走规范问答 | 读、写；发布视项目是否授予 |
| 只读访客 | 读；可走规范问答（若已开通 `spec_ask`） | 读 |

个人空间（数据服务）按所有者可见，不做成菜单权限。

## 4. 与仓建设的关系

规范定义项目内约定；建模按约定管理逻辑表。  
指标定义、指标工厂、查询网关属于数据服务，不进建模中心。  
调度落地、质量任务执行属于开发中心或质量模块。

## 5. 非目标

- 把项目提升成租户，或让用户在登录页自助新建租户。
- 让租户在后台拖菜单、配外链、自定义路由。
- 用通用后台脚手架替换本产品的工作台信息架构。
- 做成任意勾选的权限矩阵；权限跟角色走。
- 平台模型目录 / 默认通道。
- 租户自定义任意路由、通用后台 Chat。
- 开发中心 / 质量 / 指标 AI。
- 提示词按项目分叉（本版只按租户）。

# 0.1.3 功能需求清单

产品版本 0.1.3 · 文档修订 1.2 · 状态：设计中  
依据：[00-platform.md](./00-platform.md)、[01-spec-center.md](./01-spec-center.md)、[02-modeling-center.md](./02-modeling-center.md)、[03-identity-access.md](./03-identity-access.md)

本篇把已确认的产品能力拆成**可验收条目**。模式列：`multi` 仅多租户；`standard` 仅普通模式；`both` 两种都要。角色列为空表示所有已登录且有入口权限的人。

交互原型：`npm run proto -- 0.1.3` → http://127.0.0.1:4203/  
Release 摘要：[../RELEASE.md](../RELEASE.md)  
实现拆分：`docs/tech/0.1.3-checklist.md`

## 0. 交付边界

**本版交付：** 0.1.1 已确认能力 + **AI 能力开通** + **工作台提示词** + **规范/建模对话带本项目规范**（设计 / 问答分流）。

**本版不交付：** 平台模型目录 / 默认通道；通用后台 Chat；开发中心 / 质量 / 指标 AI；提示词按项目分叉；开发中心、沉淀优化、数据服务（原型侧栏可点，仅占位）。

**相对 0.1.1：** 身份与三套壳沿用；本版增量是仓建设下的 AI SKU、提示词槽位、对话上下文与问答只读。

1.x–6.x 沿用 0.1.1 验收（下文只列本版新增或改写的条目）。完整 0.1.1 条目见 [0.1.1 spec/04](../../0.1.1/spec/04-requirements.md)。第 7 节**改写** 0.1.1 的 2.4 / 3.2 / 3.4 / 3.7。

## 7. 交互对齐（相对 0.1.1）

| # | 需求 | 模式 | 角色 | 验收要点 |
|---|---|---|---|---|
| 7.1 | 平台点「进入」租户**每次**都要输入授权码 | multi | 平台用户 | 不因上次已绑定而跳过；码无效不能进 |
| 7.2 | 授权码可指定项目角色：全部项目同一角色，或按项目勾选角色 | multi | 租户管理员 | 不再写死只读访客；可同时勾选 AI 能力 |
| 7.3 | 工作台用户：行上仅编辑 / 删除；细节在右侧抽屉 | both | 租户管理员 | 抽屉内改资料与项目成员后点保存；指定管理员、重置密码即时生效 |
| 7.4 | 工作台项目：块 / 行切换；进入与编辑在外，删除在编辑抽屉 | both | 租户管理员 | 停用后不能进入；切换项目不列出已停用项；编辑抽屉可勾选知识库引擎 |
| 7.5 | 工作台「知识库」或项目管理编辑：按项目勾选引擎；查阅 Hive / Spark / ClickHouse / Doris 操作手册 | both | 租户管理员 | 两处勾选同一份项目设置；建表 / 改表等手册可点；未勾选的项目进项目内知识库为空 |
| 7.6 | 项目内「知识库」只读已开通引擎手册 | both | 项目成员 | 不在项目里改开通；开通只在工作台 |
| 7.7 | 工作台可按模版导入知识库；支持 JSON（`dw-ai.knowledge`）与 Markdown | both | 租户管理员 | 可下载模版；导入后按引擎出现在手册中；同 id 覆盖；可删导入篇 |

## 8. AI 能力开通

| # | 需求 | 模式 | 角色 | 验收要点 |
|---|---|---|---|---|
| 8.1 | 平台开租户 / 编辑租户：在开通模块旁勾选 AI 能力 `spec_design` / `spec_ask` / `model_design` | multi | 平台用户 | 未勾仓建设则 AI 项无效；勾仓建设时默认三项全开 |
| 8.2 | 授权码生成 / 编辑可勾选同样三项；空 = 不限制 | multi | 租户管理员 | 持码进入后有效能力 = 租户开通 ∩ 授权码 |
| 8.3 | 无 `spec_design` 且无 `spec_ask`：「AI 设计规范」可见但禁用 | both | 项目成员 | 文案「本组织未开通此项」；普通模式三项默认开，不出现未开通 |
| 8.4 | 无 `model_design`：各层「AI 设计」可见但禁用 | both | 项目成员 | 同上文案 |
| 8.5 | `spec_design` 同步仍须 `spec:write`；`spec_ask` 有 `spec:read` 即可；`model_design` 写入仍须 `model:write` | both | — | 不能靠拼 URL 绕过；无写权限不能提交 |
| 8.6 | Session / 前端 `hasAiCap(cap)` 与 `hasModule` 并列 | both | — | 平台访客按交集计算 |

## 9. 工作台提示词

| # | 需求 | 模式 | 角色 | 验收要点 |
|---|---|---|---|---|
| 9.1 | 设置（租户）在大模型下方展示三个槽位：`spec.system`、`spec.ask.system`、`model.system` | both | 租户管理员 | 产品内置中文默认，打开即用 |
| 9.2 | 每槽可改、可「恢复默认」；只存相对默认的覆盖 | both | 租户管理员 | GET 带回 defaults / overrides / effective |
| 9.3 | 页上展示可用占位符：`{{project}}` `{{domains}}` `{{layers}}` `{{roots}}` `{{grades}}` `{{layer}}` `{{focus_table}}` | both | 租户管理员 | 代发前由服务端替换，不在浏览器替换 |
| 9.4 | 未开大模型：对话走内置草案，不读租户槽位；页上提示「先启用大模型，提示词才会用于代发」 | both | — | 改了提示词但未开模型，对话结果不随槽位变 |
| 9.5 | 提示词明文回给租户管理员；密钥仍不回传 | both | 租户管理员 | 平台设置无提示词 |
| 9.6 | 提示词按租户，不按项目分叉 | both | — | 同一租户各项目共用槽位，注入的是**当前项目**摘要 |

## 10. 规范 / 建模 AI 加深

| # | 需求 | 角色 | 验收要点 |
|---|---|---|---|
| 10.1 | 规范设计代发附带当前项目主题域 / 分层 / 等级 / 词根摘要 | 写规范 + `spec_design` | 默认增量补全；无声明不覆盖整包分层 |
| 10.2 | 覆盖已有编码必须勾选「覆盖已有编码」 | 同上 | 未勾选则跳过已存在编码 |
| 10.3 | 草案每条尽量带一句理由 | 同上 | 引擎 rationale 或模型说明可见 |
| 10.4 | 无 `spec:write` 或仅开通 `spec_ask`：走问答槽，只出文字，右侧无同步按钮（草案只读或不出现） | 读规范 + `spec_ask` | 不能从问答写入规范 |
| 10.5 | 同时有设计能力与写权限：默认设计，可切问答 | 项目管理员 | 切到问答后同步按钮消失 |
| 10.6 | 建模 AI 代发带本层规则、已有表名、主题域编码；改表带当前字段 | 读模型 + `model_design` | 页上标明「已带本项目规范」 |
| 10.7 | 采纳前可与当前表对比（沿用表版本）；写入须 `model:write` | 写模型 | 新建草稿；改已有表记版本 |
| 10.8 | 已开大模型：system = 有效提示词 + 注入的项目摘要，不再使用写死的一句人设 | — | body 带 `slot`、`projectId`（规范页必带） |
| 10.9 | 代发失败：提示后回退内置草案 | — | 与现建模页一致 |
| 10.10 | ODS→DWD / DWD→DWS 发布前规范校验失败信息可读 | 写模型 / 发布 | 指出规则与字段；本版不强制生成走 LLM |

## 11. 非目标

与 [00-platform.md](./00-platform.md) 第 5 节一致，本版不做：

- 平台模型目录 / 默认通道
- 租户自定义任意路由、通用后台 Chat
- 开发中心 / 质量 / 指标 AI
- 提示词按项目分叉
- 登录页自助新建租户，或把项目提升成租户
- 任意勾选的权限矩阵
- 以 Casdoor 等外部 IdP 作为本版登录主路径

## standard 模式前端登录页 + 令牌链路（完成）

承接上文「遗留：standard 前端登录页尚未实现」。另把标准模式的账号管理端点也做完了。

**后端（账号管理，`dw-lineage/sql-tools/`）**
- `V3__local_auth.sql` 三方言扩列 `is_admin`（V3 未提交，故直接扩而非开 V4）；
  `LocalUserRow`/`LocalUserRepository`/`JdbcLocalUserRepository` 同步；新增
  `countEnabledAdmins()`（**只数启用的管理员**，停用的管理员救不了场）。
- `auth/CurrentLocalUser`：身份解析唯一入口，**每次都回查库**（停用立即生效；`isAdmin`
  以库为准，否则被撤权的人还能用旧令牌管账号）。standalone 返回 id=0 的占位行。
- `auth/LocalUserService` + `LocalUserController`（`/api/users`，全部方法首行 `requireAdmin()`）。
  两条防锁死规则：`assertNotSelf`（主力，可经 HTTP 触发）与 `guardLastEnabledAdmin`
  （**在当前 HTTP 路径下不可达** —— 因为 requireAdmin 已保证 actor 是启用管理员，
  target 又是另一个人时必有两个管理员；保留它作为非 HTTP 调用方的最后一道闸）。
  这个「哪条规则才是主力」的推理写进了类注释，避免下一个人误以为 guard 在保护什么。
- `controller/TenantAdminController`：写操作从 `!isMulti()` 改为 `current.requireAdmin()`
  （此前登录生效后**任何普通用户仍能删租户**）；读操作（/context、列表）不放管理员，切换器要用。
  multi 仍显式 403「租户归组织平台管」，行为未变。
- `auth/LocalUserService` 的 `@Transactional`：停用/删除/重置密码都**立刻撤销刷新令牌**，
  否则被停用的人能一直用 refresh 换新 access。

**前端（`dw-lineage/sql-tools-vue/`）**
- 新增 `stores/auth.ts`：standard 本地会话唯一入口。令牌键 `sql-tools.accessToken` /
  `refreshToken` / `tokenExp`，**刻意不复用**壳那条链路的 `sql-tools.bootToken*` ——
  壳给的令牌前端没法自己续（只能向壳要），自登录的能拿 refresh 换，混在一个键里
  401 时分不清该走哪条。登录/续期/登出用**裸 fetch**（走 axios 实例会递归、且带死令牌）。
- 新增 `config/api.ts`：`API_BASE_URL` + `apiUrl()`，让裸 fetch 与 axios 共用一个基址且不成环。
- `stores/tenant.ts`：`currentAuthHeaders()` 改为 `authAccessToken() || currentAccessToken()`。
- `utils/request.ts`：401 分流 —— standard 走 `refreshAccess()` 后重试一次，失败 reload
  让守卫送去登录页；multi 原逻辑不动。请求前加「快到期就先换」。
- 新增 `pages/login.vue`（`/lineage/login`，是 LINEAGE_HOME 的**兄弟**而非子路由，
  不能带侧边栏/顶栏）、`components/UserMenu`（含登出 + 改显示名/改密码 ——
  **这是唯一的登出口**，改密成功后主动退一次，因为后端已作废全部 refresh）、
  `pages/settings/users.vue`（账号管理）。
- `router/index.ts`：登录守卫只看 `hasSession()`，**不看 access 是否过期**（access 15 分钟，
  按它拦会把不该重登的人赶走；真过期由 401 拦截器兜）。加 `meta.adminOnly`。
- `config/nav.ts`：`NavItem` 加 `adminOnly`，「账号管理」仅 standard+管理员可见。
- `main.ts`：standard 且已登录时 `await loadMe()` **在挂载前**（`visibleNavGroups()` 是
  setup 里一次性求值的，挂载后再拉菜单会少一项）；未登录时跳过 `refreshDefaultCatalog`/
  `verifyContext` —— 它们必然 401，会和守卫的重定向抢着跳。
- `pages/login.vue` 的重定向只接受站内路径且挡掉 `//`（协议相对地址是开链）。

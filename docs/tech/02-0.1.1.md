交互对照：`npm run proto -- 0.1.1`（4183）  
本版清单：[0.1.1-checklist.md](./0.1.1-checklist.md)

在 [00-stack.md](./00-stack.md)、[01-spec-modeling.md](./01-spec-modeling.md) 之上扩展。**不改产品 spec。** Casdoor 不作为本版登录主路径。

## 1. 栈与相对 0.1.0 的增量

现有：Vue 3 控制台 + Spring Boot 3.3 + PostgreSQL 16 + Flyway（V1–V3）+ `@dw-ai/engine`。  
已有表：`tenants` / `users` / `user_tenants` / `platform_admin` / `projects` / `project_members` / 规范与表。  
JWT 开发登录已有，但把 `tenant_id` 写进 token，且 `modeler` 仍带 `spec:write`——本版要改。

| 层 | 0.1.0 | 0.1.1 增量 |
|---|---|---|
| 控制台 | `/login`、`/projects`、`/w/*` | 三套壳；普通模式不注册平台路由 |
| 登录 | 开发 JWT 或可选 Casdoor | **产品自建账号**（用户名+密码，bcrypt）；Casdoor 保留接线但不作主路径 |
| 身份 | token 内带租户 | JWT 只认人；租户由显式选择 + `X-Tenant-Id` |
| 权限 | `modeler` 可写规范 | `spec:write` 仅项目管理员 |
| 建模 | 逻辑表 + ODS/DWD 生成 | `table_versions`；每层 AI 设计；租户 LLM 代发 |

配置（启动时读一次，改须重启）：

| 项 | 含义 |
|---|---|
| `DW_AI_MODE=multi\|standard` | 部署模式；控制台同步 `VITE_DEPLOY_MODE` |
| `SECURITY_MODE=dev` | 本版默认；自建账号签发 HS256 JWT |
| `DW_AI_LLM_SECRET` | 租户大模型密钥加密用主密钥 |

## 2. 三套壳（路由与守卫）

对齐原型 `docs/product/versions/0.1.1/prototype/src/router/index.ts`。

| 壳 | 路径 | 布局 | 谁进 |
|---|---|---|---|
| 平台管理 | `/admin`、`/admin/users`、`/admin/settings` | `SystemLayout` · `shell=admin` | 平台用户；仅 `multi` |
| 工作台 | `/projects`、`/sys/users`、`/sys/roles`、`/sys/settings` | `SystemLayout` · `shell=sys` | **仅租户管理员**（普通模式为能建项目/管用户的管理员） |
| 项目 | `/w/*` | `ProjectLayout` | 当前项目成员 |

其它：`/login`；`/select-tenant`（仅 multi）；`/no-project`。

守卫要点：

- 未登录 → `/login`。
- `multi` 且已登录未选租户 → `/select-tenant`；不能进 `/projects` 与 `/w/*`。
- 平台用户未选租户 → `/admin`；进租户须有效授权码（或仍有效绑定）。
- 工作台路由：非租户管理员一律送到落点（已加入项目概况或 `/no-project`），不能靠拼 URL 进入。
- `standard`：**不注册** `/admin`、`/select-tenant`；界面无「租户」字样。
- 项目内 `/w/dev/*`、`/w/service/*`、`/w/materialize` 可继续占位，**本版不接后端交付**。
- 本版新增项目路由：`/w/model/:layer/ai`、`/w/model/:layer/:domain/:tableId/versions`。概况菜单文案为「概况」。

落点（登录或选租户后）：

```
平台用户（未持码）→ /admin
租户管理员 → /projects
其它成员且有项目 → /w（该项目概况）
其它成员且无项目 → /no-project
```

## 3. 身份

### 3.1 表（在 V3 之上）

已有：`users`（`username` 全局唯一、`password_hash`、`status`、`platform_admin`）、`user_tenants(user_id, tenant_id, tenant_role)`。

新增（建议 V4）：

```
tenant_grants (
  id, tenant_id, code UNIQUE, kind,          -- permanent | 1h | 1d | 7d
  expires_at NULL, revoked_at NULL,
  created_by, created_at
)

platform_access (
  user_id, tenant_id, grant_id,
  PRIMARY KEY (user_id, tenant_id)
)

-- 外观：平台一份、每租户一份
appearance_prefs (
  scope,          -- 'platform' | 'tenant'
  tenant_id NULL, -- platform 行为空
  theme, menu_pos,
  UNIQUE (scope, tenant_id)
)

tenant_llm (
  tenant_id PK,
  enabled, provider, base_url, model,
  api_key_enc BYTEA,          -- 服务端加密，GET 永不回传明文
  updated_at
)
```

密码：bcrypt（与 V3 种子一致）。停用（`users.status != active`）不能登录。不能停用自己、不能停用最后一个可用平台用户。

`standard`：库里仍可有一条隐式租户（如种子 `t-xinghe`），API 不暴露租户概念；平台用户不能登录。

### 3.2 会话

登录只认人，**不把当前租户写死为 token 真源**：

1. `POST /api/auth/login` `{ username, password }` → JWT：`sub=userId`、`username`、`name`、`platform_admin`。错误统一「用户名或密码错误」。
2. `GET /api/auth/tenants`：该用户可用租户（所属且未停用；平台用户列出已绑定且授权仍有效的租户）。
3. `POST /api/auth/select-tenant` `{ tenantId }`：校验成员或有效 `platform_access`；服务端记住会话租户（或签发带租户的短时 access，但校验仍以库为准）。
4. 之后业务请求带 `Authorization` + **`X-Tenant-Id`**。过滤器：用户必须对该租户有 `user_tenants` 或未过期未作废的 `platform_access`；租户停用则 403。
5. 项目请求另带 `X-Project-Id`，项目必须属于当前租户，且 `project_members` 有记录（租户管理员进工作台不强制项目成员）。

退出清 token 与当前租户。切换租户不重新登录，回到选择页再 `select-tenant`。

### 3.3 授权码与转让（仅 multi）

- 租户管理员生成/作废 `tenant_grants`。平台用户 `POST /api/auth/enter-tenant { tenantId, code }`：码有效则写入/更新 `platform_access`。
- 作废或过期：该码下已绑定进入资格全部失效（按 `grant_id` 删或判无效）。
- 转让：`POST /api/tenants/{id}/transfer-admin { userId }`。对方须为本租户未停用用户；调用者降为 `member`。平台用户持码也不能调此接口。

## 4. 权限（角色语义，无矩阵）

项目角色码仍是 `admin` / `modeler` / `viewer`。改 `Perms.java` 与 `ui/src/config/iam.ts`：

| 角色 | 权限 |
|---|---|
| admin | `spec:read` `spec:write` `model:read` `model:write` `model:publish` `iam:member` |
| modeler | `spec:read` `model:read` `model:write`（**去掉 spec:write**；发布视产品，默认无 `model:publish`） |
| viewer | `spec:read` `model:read` |

入口、按钮、提交同一套码：无 `spec:write` 则规范页只读（含导出）；无 `model:write` 则不能建改表、不能采纳 AI、不能恢复版本。

租户工作台接口另验 `user_tenants.tenant_role = admin`。平台接口验 `platform_admin`。

拉项目成员：只能选本租户 `user_tenants` 用户，不能填系统外名字。

## 5. 外观与大模型

- **外观**：平台设置只写 `scope=platform`；租户设置写该 `tenant_id`。控制台按当前壳取一份，互不污染。默认 `theme=cyan`、`menuPos=left`。
- **大模型**：仅租户设置。GET 返回 `enabled/provider/baseUrl/model/hasKey`，**不回传明文**。PUT 可只送「是否更换密钥」。密钥用 `DW_AI_LLM_SECRET` AES-GCM（或等价）落 `api_key_enc`。
- 未开启或无密钥：规范 AI / 建模 AI 走 `@dw-ai/engine` 内置草案（与原型一致）。
- 开启后：**浏览器不直连模型商**。`POST /api/ai/chat`（带租户）由 API 解密密钥代发 OpenAI 兼容 Chat Completions，把助手文本回给前端，再由引擎解析为草案。密钥不出浏览器。

## 6. 建模 AI 与表版本

新表（建议 V5，可与 V4 合并）：

```
table_versions (
  id, table_id FK warehouse_tables ON DELETE CASCADE,
  version INT,               -- 每表从 1 递增
  note, actor_user_id, created_at,
  snapshot JSONB NOT NULL,   -- TableSnapshot（表属性 + columns）
  UNIQUE (table_id, version)
)
```

`warehouse_tables` 可加 `current_version INT`（冗余，便于列表；真源仍是最新一版快照）。

规则（引擎已有 `snapshotTable` / `sameSnapshot` / `diffSnapshots`，实现窗口从原型 `packages/engine` 收进正式包）：

- 凡写入结构（手建、编辑、AI 采纳、恢复）且快照有变化，必插一版；无变化不记。
- 当前表内容 = 最新一版。历史不删、不改写。
- 恢复：把目标版 snapshot 写回表，再记一版，`note` 如「从 vN 恢复」。
- AI：对话只针对当前层；确认前不落库；新建为草稿；改已有表更新结构并记版本。无 `model:write` 只能看草案。

## 7. API 增量

规范/表/成员资源仍挂 `/api/projects/{projectId}`，见 [01-spec-modeling.md](./01-spec-modeling.md)。下列为 0.1.1 新增或语义变更。

### 鉴权与配置

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/auth/config` | `deployMode`、是否允许登录；不再把 Casdoor 当默认 |
| POST | `/api/auth/login` | 用户名密码；不强制 tenantId |
| GET | `/api/auth/me` | 用户、是否平台、当前租户、落点建议 |
| GET | `/api/auth/tenants` | 当前用户可用租户 |
| POST | `/api/auth/select-tenant` | 选定租户 |
| POST | `/api/auth/enter-tenant` | 平台用户凭授权码绑定 |
| PUT | `/api/me` | 改显示名 |
| PUT | `/api/me/password` | 改自己的密码 |

### 平台（仅 multi · platform_admin）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/platform/tenants` | 含已停用；创建时指定/新建管理员 + 空默认项目 |
| PATCH | `/api/platform/tenants/{id}` | 停用启用、模块、指定管理员 |
| GET/POST | `/api/platform/users` | 平台账号；用户名全局唯一 |
| PATCH | `/api/platform/users/{id}` | 改密码、停用启用 |
| GET/PUT | `/api/platform/appearance` | 只作用于平台壳 |

### 工作台（租户管理员）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/tenants/{id}/users` | 本租户用户；新建或拉已有账号 |
| PATCH | `/api/tenants/{id}/users/{userId}` | 停用启用、重置密码、指定某项目管理员 |
| GET/POST | `/api/tenants/{id}/projects` | 新建可导入通用规范模板 |
| GET/PUT | `/api/tenants/{id}/appearance` | 工作台+项目外观 |
| GET/PUT | `/api/tenants/{id}/llm` | 大模型；密钥不回传 |
| GET/POST | `/api/tenants/{id}/grants` | 生成授权码 |
| POST | `/api/tenants/{id}/grants/{grantId}/revoke` | 作废 |
| POST | `/api/tenants/{id}/transfer-admin` | 转让 |

`standard` 不暴露 grants / transfer / platform；工作台路径可用同一套，文案去「租户」。

### 项目增量

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/projects/{id}/tables/{tableId}/versions` | model:read |
| GET | `.../versions/{versionId}` | 某版快照 |
| GET | `.../versions/diff?from=&to=` | 对比 |
| POST | `.../versions/{versionId}/restore` | model:write |
| POST | `/api/projects/{id}/layers/{layer}/ai/chat` | model:read（写入另走确认） |
| POST | `/api/projects/{id}/layers/{layer}/ai/apply` | model:write |
| POST | `/api/ai/chat` | 已选租户；LLM 代发或标明走内置草案 |

写表（已有 PUT/POST `/tables`）在服务端记版本。`spec:write` 收口后，建模工程师调规范写接口须 403。

## 8. 前端改动面（实现窗口）

- `ui/src/router`：按第 2 节拆壳；`standard` 条件注册平台路由。
- `ui/src/layouts`：对齐原型 `SystemLayout` / `ProjectLayout`；项目顶栏切换器（可进项目 > 1 才显示，无「项目」前缀）；租户名回工作台仅租户管理员。
- `ui/src/config/iam.ts`：`ROLE_PERMS.modeler` 去掉 `spec:write`。
- `ui/src/pages`：从 0.1.1 原型迁登录/选租户/平台/工作台/设置/建模 AI/版本页（实现接 API，不接 localStorage 当生产真源）。
- 外观：按壳读对应 prefs；设置页平台无 LLM 区块。
- 占位页（开发中心等）保持只读提示即可，不接新 API。

## 9. 明确不做（本版实现）

- 不以 Casdoor / OIDC 作为必开登录；`SECURITY_MODE=oidc` 可保留但不作为 0.1.1 验收路径。
- 不实现开发中心、沉淀优化、数据服务后端。
- 不实现登录页自助开租户、权限勾选矩阵、租户自定义路由。
- 本文件只定方案，不改 `ui/src/` 与 SQL。

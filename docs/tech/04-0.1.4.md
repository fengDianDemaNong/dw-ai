## 1. 相对现状

| 处 | 0.1.3 实现 | 0.1.4 |
|---|---|---|
| 字段 | 名 / 类型 / 注释 / 等级 | 再加 `logic`（五种加工） |

## 2. 数据（Flyway V11）

`postgresql` / `mysql` 各一份：`V11__table_logic_and_lineage.sql`。H2 走 mysql 目录。

```
-- postgresql
ALTER TABLE warehouse_tables
  ADD COLUMN IF NOT EXISTS sources JSONB,
  ADD COLUMN IF NOT EXISTS joins JSONB,
  ADD COLUMN IF NOT EXISTS filter_expr TEXT;
ALTER TABLE table_columns
  ADD COLUMN IF NOT EXISTS logic JSONB;

-- mysql / H2
ALTER TABLE warehouse_tables ADD COLUMN sources JSON NULL;
ALTER TABLE warehouse_tables ADD COLUMN joins JSON NULL;
ALTER TABLE warehouse_tables ADD COLUMN filter_expr TEXT NULL;
ALTER TABLE table_columns ADD COLUMN logic JSON NULL;
```

语义：

| 列 | 空 | 有值 |
|---|---|---|
| `sources` | 回退 `createdFrom`（别名 `s`） | `[{tableId, alias}]` |
| `joins` | 无关联 | `[{leftAlias,leftColumn,rightAlias,rightColumn,type}]` |
| `filter_expr` | 生成 DML 时按分区拼 `dt = ${bizdate}` | 表级 WHERE |
| `logic` | 该列尚未定义加工 | `{kind,desc,sources,op,expr,filter}` |

`kind` 仅 `passthrough` / `transform` / `aggregate` / `derive` / `constant`。未定义加工是合法状态（演示支付明细保持空）。

快照 JSON 须含来源、关联、过滤与字段 `logic`。

## 3. API 增量

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST/PUT | `/api/projects/{id}/tables` | 写模型 | 写入结构与加工，**强制草稿**（新建默认 draft；更新把状态打回 draft），**不记版本** |
| POST | `/api/projects/{id}/tables/{tableId}/publish` | 发布模型 | body `{ note }`。状态改为 published，结构有变化才记一版 |
| POST | `.../versions/{id}/restore` | 写模型 | 写回为草稿，不记版本 |

`TableDto` 增加 `sources` / `joins` / `filter`。`ColumnDto` 增加 `logic`。

`saveTable` 不再调用 `recordIfChanged`。`syncTables` / AI 采纳 / 恢复走同一条保存。

`GET .../versions`：已发布且尚无版本时补「初始版本」。草稿不补。

## 4. 引擎

从原型 `docs/product/versions/0.1.4/prototype/packages/engine` 拷入 `packages/engine`：

- `fieldLogic.ts`：五种说明、字段表达式、字段查询 SQL、加工 DML
- `impact.ts`：下游表/字段影响
- `modelVersion.ts`：`renderAlterSql`；快照含 sources/joins/logic
- `modeling.ts`：ODS→DWD / DWD→DWS 写入 sources/joins/logic（DWS 可多源）

加工 DML 只出一份逻辑 SQL，不按方言拆，不执行。

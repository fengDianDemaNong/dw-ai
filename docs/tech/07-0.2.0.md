## 2. 项目拆分

```
组织平台 ──REST /internal/v1──► 仓建设
   │                              │
   │  heartbeat / authz / 同步项目 │  业务 /api/v1
   │                              │
   └──REST /internal/v1──► 数据地图（dw-lineage）
                              ▲
                              │ iframe ?embed=1#boot=
                         仓建设浏览器壳
```

| 进程 | 实现 UI | 实现 API | 原型 |
|---|---|---|---|
| 组织 | `dw-org/ui` → 5174 | `dw-org/api` → 18080 | 4234 |
| 仓建设 | `dw-model/ui` → 5173 | `dw-model/api` → 18081 | 4233 |
| 数据地图 | `dw-lineage/sql-tools-vue` → 5175 | `dw-lineage/sql-tools`（演示 8080 / 18082） | 5175 |
| 规则 | — | `dw-model/rules` → 7080 | — |

引擎 `packages/engine` 无用户、无租户，三种模式共用。

**禁止**：模块共库（含同一 MySQL/PostgreSQL 库名）、前端直打兄弟 `/api`、把组织库主键当跨服务 code。

## 3. 服务之间怎么传

### 3.1 浏览器只打当前进程

仓建设页只请求仓建设 `18081`。数据地图请求由 **iframe 里的 dw-lineage** 打对方 origin。组织打开仓建设只带 hash，不让仓建设再去打组织业务 API。

### 3.2 跨产品只认 code

| 字段 | 例 | 禁止当跨服务契约 |
|---|---|---|
| `tenant_code` | `xinghe` | `t-xinghe`、`1` |
| `project_code` | `trade_dw` | `p-trade`、`1` |
| `user_id` | 组织用户 id | 各产品本地账号主键 |

### 3.3 Header（模块 `/api/**`）

| 头 | multi | standard | standalone |
|---|---|---|---|
| `X-Tenant-Code` | 必填 | 不传 | 可空展示 |
| `X-Project-Code` | 必填 | 可落到默认项目 | 可空展示 |
| `X-User-Id` | 写操作必填 | 本模块用户 | 可空 |
| `Authorization` | 组织签发的 JWT（仓建设壳） | 本模块 JWT | 无或静态令牌 |

过渡：继续收 `X-Tenant-Id` / `X-Project-Id`，**非数字按 code 解析**；解析不到 → 400，不准静默落到租户 1。

### 3.4 `#boot=`

```
#boot={"userId","tenantCode","projectCode","tenantName","projectName","embed", "token"?}
```

组织 → 仓建设壳：可以带组织会话 `token` + 组织内部 id（只给壳）。  
仓建设 → 数据地图：**必须转成 code**，并 `embed: true`。

### 3.5 组织 `/internal/v1`（模块调用，模块令牌）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/registry/heartbeat` | `product` + `baseUrl` + 版本 |
| GET | `/authz/check` | `userId + tenantCode + projectCode + product + action` |
| GET | `/context` | 校验模块令牌，回用户/租户/项目摘要 |
| PUT/DELETE | 组织调模块 `/internal/v1/projects/{project_code}` | 同一 code 落镜像 |

模块 `standalone`/`standard` 不登记、不调组织。

## 4. 权限怎么落

```
可见菜单 = 平台开通 ∩ 租户启用 ∩ 可见范围 ∩ （数据地图：始终显示组）
能写 = 可见 ∩ 产品角色（或项目管理员自动管理角色）∩ authz.allow
```

| 模式 | 鉴权 |
|---|---|
| standalone | `Perms` 放行或静态令牌；头只展示 |
| standard | 本地用户 + 本库「组织角色 + 产品角色」 |
| multi | 仓建设写路径先 `GET {org}/internal/v1/authz/check`；库不存密码 |

现有 `Perms.admin/modeler/viewer` 只覆盖仓建设，实现时改成两段角色，与原型分栏一致。

## 6. 实现阶段

**P0 对齐原型壳（本迭代先做）**

1. 仓建设菜单：数据地图 + 设置（外观/成员/知识库/元数据服务/数据地图设置）。  
2. 菜单风格 drawer/left/top；快捷栏 + `<`。  
3. 主题 + 菜单栏颜色（工作台设置 + 项目外观）；API `appearance_prefs.menu_color`。  
4. iframe embed dw-lineage；boot 用 code。  
5. 请求头同时带 `X-*-Code`（从当前租户/项目的 `code` 取）。

**P1 契约**

6. 组织 `authz/check` 入参改 code。  
7. 创建项目 `PUT` 已登记产品 `{project_code}`。  
8. 仓建设 `multi` 写路径走远程 authz。  
9. 分层规范按 `project_id` 隔离（空项目可导入模板）。

**P2 拆包（后置）**

10. 组织 / 仓建设独立安装包与独立库。  
11. 质量 / 服务独立进程。

## 7. 数据要点

- 规范、表、分层规则带 `project_id`（组织侧主键，仅本库）。出进程用 `project_code`。  
- `appearance_prefs`：`theme`、`menu_pos`（`drawer|left|top`）、`menu_color`（`ink|light|cyan|blue|green|orange`）。  
- 产品角色表：`project_id + user_id + product + role`。  
- 服务注册：内存或表，按 `product` 一份 `baseUrl` + 心跳时间。

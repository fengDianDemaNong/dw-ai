## 1. 相对现状

| 处 | 现状 | 0.1.3 |
|---|---|---|
| 规范助手 | `ui/src/pages/spec/copilot.vue` 只走 `replySpecChat`，不调 `/api/ai/chat` | 先代发再解析草案；问答槽只出文字 |
| 建模 AI | 会代发，但 `AiService` system 写死「你是数仓建模助手…」，不带主题域 / 分层 / 词根 | system = 有效槽位 + 项目摘要 |
| 开通 | 只有模块 | `tenant_licenses.ai_caps` |

## 2. 数据（Flyway V9 + V10）

现网 Postgres 在 V8。`postgresql` / `mysql` 各一份：`V9__ai_caps_and_prompts.sql`、`V10__project_engines_and_knowledge.sql`。H2 走 mysql 目录。启动仍可能需要现有的 Flyway ignore 标志。

### 2.1 许可与授权码

```
-- postgresql
ALTER TABLE tenant_licenses ADD COLUMN IF NOT EXISTS ai_caps JSONB NOT NULL DEFAULT '[]'::jsonb;
ALTER TABLE tenant_grants   ADD COLUMN IF NOT EXISTS ai_caps JSONB NOT NULL DEFAULT '[]'::jsonb;

-- mysql / H2
ALTER TABLE tenant_licenses ADD COLUMN ai_caps JSON NULL;
UPDATE tenant_licenses SET ai_caps = '[]' WHERE ai_caps IS NULL;
ALTER TABLE tenant_grants ADD COLUMN ai_caps JSON NULL;
UPDATE tenant_grants SET ai_caps = '[]' WHERE ai_caps IS NULL;
```

语义：

| 列 | 空数组 | 有值 |
|---|---|---|
| `tenant_licenses.ai_caps` | 仓建设已开则默认三项全开 | 仅列出的能力 |
| `tenant_grants.ai_caps` | 不限制（取租户侧） | 与租户取交 |

合法码：`spec_design` / `spec_ask` / `model_design`。未开 `warehouse` 时三项均无效。

实体：`TenantLicenseEntity`、`TenantGrantEntity` 增加 `aiCaps`（`JsonbStringTypeHandler`）。  
DTO：`TenantDto` / `CreateTenantReq` / `PatchAdminTenantReq` / `LicenseDto` / `GrantReq` / `GrantDto` 增加 `List<String> aiCaps`。

`GET /api/auth/me` 与 session 快照带 `aiCaps`（已按租户 ∩ 授权码算好），前端 `hasAiCap(cap)` 与 `hasModule` 并列。

### 2.2 提示词覆盖

```
CREATE TABLE tenant_ai_prompts (
  tenant_id  VARCHAR(64) NOT NULL,
  slot       VARCHAR(64) NOT NULL,
  body       TEXT NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant_id, slot),
  CONSTRAINT fk_aip_tenant FOREIGN KEY (tenant_id) REFERENCES tenants (id) ON DELETE CASCADE
);
```

MySQL 用 `DATETIME(3)` 代替 `TIMESTAMPTZ`。只存相对默认的覆盖。未知 `slot` 拒绝写入。

默认正文放 `packages/engine/src/aiPrompts.ts`（或 `services/api` 资源文件与引擎 key 对齐），前后端同一套槽位：

| slot | 用途 |
|---|---|
| `spec.system` | 规范设计 |
| `spec.ask.system` | 规范问答 |
| `model.system` | 分层建模 |

占位符（服务端替换，不在浏览器替换）：`{{project}}` `{{domains}}` `{{layers}}` `{{roots}}` `{{grades}}` `{{layer}}` `{{focus_table}}`。

默认正文要比「一句话人设」完整：角色、项目上下文、增量/只读约束、输出结构。与原型 `docs/product/versions/0.1.3/prototype/src/config/aiPrompts.ts` 对齐后拷到 `packages/engine`。

### 2.3 项目引擎与导入手册（Flyway V10）

```
-- 项目开通哪些引擎知识库；空 = 项目内知识库为空
ALTER TABLE projects ADD COLUMN engines JSONB NOT NULL DEFAULT '[]'::jsonb;  -- pg
ALTER TABLE projects ADD COLUMN engines JSON NULL;                          -- mysql，空则当 []

CREATE TABLE tenant_knowledge_articles (
  tenant_id    VARCHAR(64)  NOT NULL,
  engine       VARCHAR(32)  NOT NULL,
  article_id   VARCHAR(128) NOT NULL,
  title        VARCHAR(256) NOT NULL,
  summary      TEXT,
  body         TEXT,
  source_url   TEXT,
  source_label VARCHAR(256),
  sections     JSONB,          -- mysql 用 JSON：[{heading,body,sql,sqlCaption,note}]
  notes        JSONB,
  imported_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  imported_by  VARCHAR(64),
  PRIMARY KEY (tenant_id, engine, article_id),
  CONSTRAINT fk_tka_tenant FOREIGN KEY (tenant_id) REFERENCES tenants (id) ON DELETE CASCADE
);
```

`engine` 仅 `hive` / `spark` / `clickhouse` / `doris`。内置手册不入库，跟前端/引擎静态资源走。导入篇按租户隔离，所有已开通该引擎的项目可见。

`PATCH /api/projects/{id}` 增加 `engines: string[]`（已有项目补丁接口，只扩字段）。

## 3. API 增量

挂现有租户管理员 / 成员鉴权。不新开通用 Chat。

### 3.1 提示词

| 方法 | 路径 | 谁 | 说明 |
|---|---|---|---|
| GET | `/api/tenants/{id}/ai-prompts` | 租户管理员 | `{ defaults, overrides, effective }`；`effective[slot] = overrides[slot] ?? defaults[slot]` |
| PUT | `/api/tenants/{id}/ai-prompts` | 租户管理员 | body：`{ overrides: { slot: body } }`；空串或与默认相同则删覆盖（恢复默认） |

平台设置无此接口。GET **明文**回提示词；LLM 密钥仍不回传。

### 3.2 开通与授权码

授权码 body 带 `aiCaps: string[]`。平台开租户 / 编辑**不**接收 AI 勾选。

- 平台创建 / `PATCH /api/platform/tenants/{id}`：只写模块。仓建设开通则 `tenant_licenses.ai_caps` 写三项，否则写空。忽略请求里的 `aiCaps`。
- `POST/PATCH /api/tenants/{id}/grants`：写 `tenant_grants.ai_caps`。空 = 不限制。
- `POST /api/auth/enter-tenant` 后的 me / license：返回交集后的 `aiCaps`。

### 3.3 代发

`POST /api/ai/chat` 与 `POST /api/projects/{id}/layers/{layer}/ai/chat`：

body 增加：

```
slot: "spec.system" | "spec.ask.system" | "model.system"
projectId: string   // 规范页必带；建模层 chat 已有 project
```

服务端：

1. `requireTenant`；规范槽验 `spec:read`，建模槽验 `model:read`。
2. `hasAiCap`：`spec.system` → `spec_design`；`spec.ask.system` → `spec_ask`；`model.system` → `model_design`。无能力 403。
3. 未开 LLM 或无密钥：返回 `{ source: "builtin" }`，**不读**租户槽位。
4. 已开：`system = replace(effective[slot], 项目摘要)`，再拼 user / history；不再使用写死人设。
5. 代发失败：502 或返回 `{ source: "builtin", fallback: true, error }`，前端提示后走引擎草案。

项目摘要（规范页必带 `projectId`）：主题域 / 分层 / 等级 / 词根编码与名称，截断防超长。建模另注入本层规则、已有表名、`focus_table` 字段。

`POST .../ai/apply` 仍须 `model:write` + `model_design`。规范同步仍走现有 spec 写接口，须 `spec:write` + `spec_design`。

对话 vs 确认（设置页必须写清，实现不得把确认写进 chat）：

| 功能 | 提示词槽 | 对话 | 确认后 | 会改的数据 |
|---|---|---|---|---|
| 规范设计 | `spec.system` | `POST /api/ai/chat` | `PUT /api/projects/{id}/spec` | 主题域 / 分层 / 等级 / 词根 |
| 规范问答 | `spec.ask.system` | `POST /api/ai/chat` | 不写库 | 无 |
| 建模对话 | `model.system` | `POST .../layers/{layer}/ai/chat` | 不写库 | 无 |
| 建模确认 | 无 | — | `POST .../layers/{layer}/ai/apply` | 本层表 / 草稿；改已有表记版本 |
| ODS→DWD / DWD→DWS | 无 | 不调模型 | `POST .../tables` 或 `/drafts` | 目标层草稿或表 |

### 3.4 知识库

| 方法 | 路径 | 谁 | 说明 |
|---|---|---|---|
| GET | `/api/knowledge/manuals` | 已登录 | 内置手册（可 `?engine=`）；不读租户导入 |
| GET | `/api/tenants/{id}/knowledge` | 租户成员 | 本租户导入篇 |
| POST | `/api/tenants/{id}/knowledge/import` | 租户管理员 | body：原文 + `filename`；`mode=merge\|replace-engine`。解析 JSON（`kind=dw-ai.knowledge`）或 Markdown |
| DELETE | `/api/tenants/{id}/knowledge/{engine}/{articleId}` | 租户管理员 | 只删导入篇，不动内置 |
| PATCH | `/api/projects/{id}` | 租户管理员 | 增加 `engines` |

导入同 `tenant_id + engine + article_id` 覆盖上一篇。解析失败 400，列出 warnings。

## 5. 引擎

- 默认槽位正文与占位符文档与前端设置页同一份 key。
- `replySpecChat` / `replyModelChat` 继续负责解析草案 / 兜底；代发成功时用模型文本再解析，失败回退现有内置逻辑。
- 规范设计默认增量；覆盖仍看前端 `overwrite` 勾选。草案条目带 `rationale`（已有则展示）。

## 6. 交互对齐（相对 0.1.1）

多数接口已有，按原型改前端与少量校验：

| 行为 | 实现要点 |
|---|---|
| 平台进入租户每次输码 | `POST /api/auth/enter-tenant` 不因已绑定跳过 |
| 授权码项目角色 | `tenant_grants.project_scopes` / `default_role`；进项目取授权角色 |
| 用户抽屉 | 现有 PATCH 用户 / 成员；指定管理员、重置密码即时生效 |
| 项目块/行、停用 | `projects.status`；停用后 enter / 切换列表排除 |
| 项目编辑勾选引擎 | `PATCH` 写 `projects.engines`，与知识库页同一字段 |

## 7. 知识库实现要点

- 内置手册：静态资源，内容来自各引擎官网 DDL（Hive LanguageManual、Spark SQL Reference、ClickHouse MergeTree、Doris CREATE/ALTER）。不进租户库。
- 导入：与原型 `knowledgeIo.ts` 同一套 `kind=dw-ai.knowledge` JSON 与 Markdown 头。解析在 `packages/engine`，API 只落库。
- 展示：`merge(内置, 导入)`，同 engine + 同 article_id 用导入覆盖展示。
- 开通：只改 `projects.engines`。项目成员只读。

## 8. 明确不做（本版实现）

- 平台模型目录 / 默认通道
- 租户自定义路由、通用后台 Chat
- 开发中心 / 质量 / 指标 AI
- 提示词按项目分叉
- 不强制 ODS→DWD / DWD→DWS 生成走 LLM
- 知识库不接远程官网实时抓取；不支持自定义引擎 slug
- 本文件只定方案；实现按 [0.1.3-checklist.md](./0.1.3-checklist.md) 在实现窗口改 `ui/src/` / `services/api` / `packages/engine`

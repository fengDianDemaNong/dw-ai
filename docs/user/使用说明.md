# 智仓使用说明（0.1.3）

安装包运行、换库、灌演示数据、升级与备份。功能怎么用、界面说明见 **[产品手册](./产品手册.md)**。产品能力清单见 [0.1.1 Release](../product/versions/0.1.1/RELEASE.md)。开发者构建见仓库根 [README.md](../../README.md)。

当前交付：**规范中心**、**建模中心**，以及登录 / 租户工作台 / 平台管理。开发中心、沉淀优化、数据服务尚未上线，控制台不会出现。

---

## 1. 环境

- **Java 17** 或以上（`java -version`）
- 默认 **不必** 安装数据库（用安装目录下的 H2 文件库）
- 可选：MySQL 8 或 PostgreSQL 16，作元数据库

---

## 2. 安装与启动

解压 `dw-ai-0.1.3.tar.gz`，进入目录。

1. 按需改 `conf/env.sh`（端口、`DW_AI_MODE=multi|standard`、密钥）。**不要填 `DB_URL` 即使用 H2。**
2. `./bin/start.sh`
3. 浏览器打开 http://127.0.0.1:8080/

| 脚本 | 作用 |
|---|---|
| `./bin/start.sh` | 启动（Flyway 建表；空库自动创建平台用户 `admin`） |
| `./bin/status.sh` | 是否在跑、健康检查 |
| `./bin/stop.sh` | 停止 |
| `./bin/seed.sh` | **手动**灌演示租户与张三/李四（须已经成功启动过一次） |

首次启动后即可用 **`admin` / `admin123`** 进平台后台（开通租户）。张三等演示账号仍须 `seed.sh`。请登录后改密；也可在 `conf/env.sh` 设 `BOOTSTRAP_ADMIN_PASSWORD`。

H2 数据文件：`data/dwai.mv.db`（目录随启动创建）。备份即复制 `data/`。

---

## 3. 换 MySQL 或 PostgreSQL

在 `conf/env.sh` 设置后重启：

```bash
# MySQL
DB_URL=jdbc:mysql://127.0.0.1:3306/dwai?useSSL=false&allowPublicKeyRetrieval=true&characterEncoding=utf8
DB_USER=dwai
DB_PASSWORD=dwai

# PostgreSQL
DB_URL=jdbc:postgresql://127.0.0.1:5432/dwai
DB_USER=dwai
DB_PASSWORD=dwai
```

库要先建好（空库即可）。也可设 `DB_TYPE=mysql` 或 `postgresql` 覆盖误判。换库后重新 `start.sh` 再 `seed.sh`。

## 4. 账号

登录页不列出这些账号，请从这里或 [产品手册](./产品手册.md) 查阅。

| 用户名 | 密码 | 何时有 | 用途 |
|---|---|---|---|
| `admin` | `admin123` | 首次启动自动创建 | 平台用户（仅多租户）。开通租户、管平台用户。进已有租户仍须授权码 |
| `张三` | `123456` | `seed.sh` 之后 | 星河租户管理员；交易数仓项目管理员 |

种子码 `XINGHE-DEMO` 只在执行 seed 后存在。

`DW_AI_MODE=standard` 时不要用 `admin` 登录；用张三进工作台。

## 5. 控制台怎么用

完整功能说明和截图见 [产品手册](./产品手册.md)。下面是最短路径。

### 多租户（默认）

登录 → 若有多个组织则选租户 → 租户管理员进工作台（用户、项目、设置）；普通成员进已加入的项目。

### 普通模式

`DW_AI_MODE=standard` 后重启。无平台后台、无「租户」字样。管理员进工作台，其他人进项目。

### 规范中心

项目侧栏：AI 设计规范、主题域、分层、数据等级、词根、导入导出。**只有项目管理员能改规范。**

### 建模中心

按分层看表、从 ODS 生成 DWD、从 DWD 生成 DWS、规范校验、每层 AI 设计表、表版本（历史 / 对比 / 恢复）。

建议路径：规范就绪 → 登记或查看 ODS → 生成下一层 → 审核发布。

## 6. 安装包升级教程

发布物有两种，都在 `release/`（或交付给你的压缩包）：

| 包 | 文件名示例 | 何时用 |
|---|---|---|
| 完整包 | `dw-ai-0.1.3.tar.gz` | 新装；或第三方 jar 有变化 |
| 增量包 | `dw-ai-0.1.3-app.tar.gz` | 只换业务代码和控制台，**不带** `libs/*.jar` |

当前安装目录里看 `VERSION` 可知正在跑哪一版。`libs/.deps-hash` 与新完整包里的同名文件一致，说明依赖没变，可以用增量包。

### 6.1 升级前

1. 通知使用者，准备短暂停机。
2. **备份**（见第 7 节）：至少备份 `conf/env.sh` 和数据（H2 的 `data/`，或 MySQL/PG dump）。
3. 记下安装根目录，下文称为 `INSTALL`（例如 `/opt/dw-ai` 或解压后的 `dw-ai-0.1.1`）。
4. 停服务：

```bash
cd "$INSTALL"
./bin/stop.sh
./bin/status.sh    # 应提示未运行
```

### 6.2 判断用完整包还是增量包

```bash
# 当前安装
cat "$INSTALL/VERSION"
cat "$INSTALL/libs/.deps-hash" 2>/dev/null || echo "（旧包没有 hash，请走完整包）"

# 新完整包解压后对比
tar -tzf dw-ai-0.1.3.tar.gz | head
```

- 新包带 `app/dw-ai-api.jar` 和 `libs/*.jar`，且 `.deps-hash` **与现网相同** → 第 6.3 节增量升级。
- hash **不同**、没有 `.deps-hash`、或目录结构还是旧的胖 jar（只有 `libs/dw-ai-api-*.jar`、没有 `app/`）→ 第 6.4 节完整升级。

不确定时一律用完整包，只要不覆盖 `conf/` 和 `data/` 即可。

### 6.3 增量升级（只换程序）

```bash
mkdir -p /tmp/dw-ai-up && tar -xzf dw-ai-0.1.3-app.tar.gz -C /tmp/dw-ai-up
NEW=/tmp/dw-ai-up/dw-ai-0.1.3-app   # 以包内实际目录名为准

cp "$NEW/app/dw-ai-api.jar" "$INSTALL/app/dw-ai-api.jar"
rm -rf "$INSTALL/web" "$INSTALL/libs/web"
cp -R "$NEW/web" "$INSTALL/web"
cp "$NEW/bin/"*.sh "$INSTALL/bin/"
chmod +x "$INSTALL/bin/"*.sh
# 可选：更新演示 SQL 脚本（不会自动执行）
cp "$NEW/sql/"*.sql "$INSTALL/sql/" 2>/dev/null || true
printf '%s\n' "0.1.3" > "$INSTALL/VERSION"   # 或复制 $NEW/VERSION

./bin/start.sh
./bin/status.sh
```

不要复制增量包里的空 `libs/`（没有第三方 jar）。**不要**用新包的 `conf/env.sh` 覆盖现场配置。

### 6.4 完整升级（含依赖或目录结构调整）

适用于：依赖变更；或从 **0.1.0 胖 jar 布局** 升到 **0.1.2**（`app/` + `libs/*.jar` 分离）。

```bash
mkdir -p /tmp/dw-ai-up && tar -xzf dw-ai-0.1.3.tar.gz -C /tmp/dw-ai-up
NEW=/tmp/dw-ai-up/dw-ai-0.1.3

# 1）先保住配置和数据
cp "$INSTALL/conf/env.sh" /tmp/env.sh.bak
# H2：确认 data/ 在 INSTALL 下；不要删

# 2）同步程序（覆盖 app、libs 第三方 jar、控制台、脚本、sql）
mkdir -p "$INSTALL/app" "$INSTALL/libs" "$INSTALL/web" "$INSTALL/sql" "$INSTALL/bin"
cp "$NEW/app/dw-ai-api.jar" "$INSTALL/app/dw-ai-api.jar"
rm -rf "$INSTALL/libs"/*.jar "$INSTALL/web" "$INSTALL/libs/web"
cp "$NEW/libs/"*.jar "$INSTALL/libs/"
cp "$NEW/libs/.deps-hash" "$INSTALL/libs/.deps-hash"
cp -R "$NEW/web" "$INSTALL/web"
cp "$NEW/bin/"*.sh "$INSTALL/bin/"
chmod +x "$INSTALL/bin/"*.sh
cp "$NEW/sql/"*.sql "$INSTALL/sql/"
cp "$NEW/VERSION" "$INSTALL/VERSION"
# 可选：新版 conf/application.yml 若有新增项，手工合并，不要整文件覆盖 env.sh
cp /tmp/env.sh.bak "$INSTALL/conf/env.sh"

# 3）若从 0.1.0 升级：可删除旧胖 jar，避免误用
# rm -f "$INSTALL/libs/dw-ai-api-0.1.0.jar"

./bin/start.sh
./bin/status.sh
```

启动时 Flyway 会按新版本 **自动补表结构**。不要对生产库再跑 `seed.sh`（会按演示主键删插样例数据）。

浏览器强刷或清缓存后再打开控制台。`http://127.0.0.1:8080/` 能登录、规范/建模页正常即完成。

### 6.5 失败回退

1. `./bin/stop.sh`
2. 把备份的 `app/`、`libs/`、`bin/` 拷回（完整升级失败时用升级前整目录副本最稳妥）
3. 还原 `conf/env.sh` 和 H2 的 `data/`（或还原数据库 dump）
4. `./bin/start.sh`

## 7. 备份

升级前建议把整个安装目录打一份 tar（停机后）：

```bash
./bin/stop.sh
tar -czf /tmp/dw-ai-backup-$(date +%Y%m%d).tar.gz -C "$(dirname "$INSTALL")" "$(basename "$INSTALL")"
```

| 内容 | 怎么备份 |
|---|---|
| H2 | 停止后复制整个 `data/`（主要是 `dwai.mv.db`） |
| MySQL / PostgreSQL | 用 `mysqldump` / `pg_dump` 备份元数据库 |
| 现场配置 | `conf/env.sh`（切勿提交到公开仓库） |
